## 0. 结论（先看）

`0xFFAB00` 是**服务菜单项目编号（service menu item code）** `N`，范围 `0x000–0x125`（294 项）。

三条独立证据：

1. **并行的 25 字节标签表**：`0x3324 + N*25` 是 ASCII 服务菜单标签，例如：
   - `N=0x110` → `"3-224[T]  FB GAIN 1.8"`
   - `N=0x11A` → `"3-234[T]  FB GAIN 70"`
   - `N=0x11B` → `"3-235[T]  CART LIMIT 1.8"`
   - `N=0x125` → `"3-245[T]  CART LIMIT 70"`
2. **校准值数组**：`0x1FE2` 把 `N` 映射到 `0xFFA948 + N`（371 B 内部设置块中的**每项 1 B 基址**），并返回服务菜单分组号；`r3l=1/3` 的实际应用目标见 §6.2/§6.3。
3. **应用/保存逻辑**：`0x1662` 对 `N=0x000/0x0F2/0x101` 及分组 `r3l=1/2` 的项写入校准值；`0x162E` 对 `r3l=3` 的 54 个 `FALC/MTR/TXG` 三元组写入 `0xFFAA79+(N-0x45)/3` 共享数组；`0xDCBA` 退出服务模式时把 `N` 保存到 `FRAM[0x0344]`、子码保存到 `FRAM[0x0346]`。

因此：

- `0x27A8 + N*10` 的 10 字节表是**服务菜单项目描述表**。
- 表尾的 `u32` 是**该项目对应的频段频率**（1.85 / 3.57 / 7.1 / … / 70.25 MHz）。
- `N=0x110–0x11A` 是 **FB GAIN 1.8…70** 校准项；`N=0x11B–0x125` 是 **CART LIMIT 1.8…70**。
- `r3l=3` 的 162 项（`0x045–0x0E6`）正好是 **54 个 `FALC/MTR/TXG` 三元组**，共享 54 B 数组。
- `0xFFAB02` 是 **0–7 的子码/页号**。

> **对 5 MHz 发射的结论**：`SPN` 只选择服务菜单项目，不写 `FRAM[0x0007]`、不写 `0xFF2007`、不写 TX 频段表 `0x32B2A`，所以不能用 `SPN` 打开 5 MHz 发射。
> `0x2680` 会通过 `0xA0C2` 切换当前波段/模式；例如 `SPN 0114`（FB GAIN 14）会把当前波段切到 14 MHz。它是有副作用的项目选择，不是只读操作。

## 1. 存储与索引关系

| 名称 | RAM | FRAM | 宽度 | 说明 |
|---|---|---|---|---|
| 服务菜单项目号 `N` | `0xFFAB00` | `0x0344–0x0345` | u16 BE | `0x000–0x125` |
| 子码/页号 `S` | `0xFFAB02` | `0x0346–0x0347` | u8（`0xFFAB03` 随 2B 块保存，未见直接引用） | `0–7` |
| 10 B 项目描述 | `0x27A8 + N*10` | ROM | 10 B | 本文 §2 |
| 25 B 项目标签 | `0x3324 + N*25` | ROM | 25 B ASCII | 本文 §5 |
| 项目校准值（`r3l=0/2`） | `0xFFA948 + N` | `0x000A + N` | 1 B | `0x1FE2` |
| `r3l=1` 特殊组 | `0xFFAA6E + (N-0x17)` | `0x0130 + (N-0x17)` | 1 B × 11 | `0x1662` |
| `r3l=3` 共享组 | `0xFFAA79 + (N-0x45)/3` | `0x013B + (N-0x45)/3` | 1 B × 54 | `0x162E` |
| VDD/ALC/IDD 表头 | `0xFFAAAF/0xFFAAB0/0xFFAAB1` | `0x0171/0x0172/0x0173` | 1 B × 3 | `0x1662` |
| 当前波段号 | `0xFFAAC6` 低 4 位 | `0x030A`（2 B） | 低字节 | `0x2680` 写入 |
| 当前模式/子模式 | `0xFF206C` 低 4 位 | — | RAM | `0x2680` 写入 |
| 子模式标志 | `0xFFAB23` 低 3 位 | — | RAM | `0x2680` 写入 |

400 B 用户设置块的装载：

```text
0x8F7E: r2=0x00C8, r1=0x0300, er3=0xFFAABC, jsr 0xA4E2   ; 0x0300-0x03C7 -> 0xFFAABC
0x8FA6: r2=0x00C8, r1=0x03C8, er3=0xFFAB84, jsr 0xA4E2   ; 0x03C8-0x048F -> 0xFFAB84
```

`0xFFAB00 = 0xFFAABC + 0x44` → **FRAM `0x0344`**；`0xFFAB02 = 0xFFAB84 + (0x0346-0x03C8)` → **FRAM `0x0346`**。

退出服务模式 `0xDCBA`：

```text
dcba: jsr 0x8EF0      ; 371 B 0xFFA948 -> FRAM 0x000A
dcbe: jsr 0x932A      ; 2 B 0xFFAB00 -> FRAM 0x0344
dcc2: jsr 0x9338      ; 2 B 0xFFAB02 -> FRAM 0x0346
dcc6: bclr #7,@0xFF2020
...
```

`0x8EF0` 写 371 B（`r2=0x173`，`r1=0x000A`，`er3=0xFFA948`）。因此服务菜单项目 `N` 的校准值会随 371 B 块一起持久化到 `FRAM[0x000A + N]`。

## 2. 10 字节表格式

```text
0x27A8 + N*10:
  +0  b0   flags
  +1  b1   mode flags + 高 4 位组号
  +2  b2   未使用（0x2680 不读）
  +3  b3   波段号（低 4 位）
  +4  b4   模式（低 4 位）
  +5  b5   子模式（低 3 位）
  +6  u32  频段频率（大端，Hz）
```

### 2.1 逐位/逐字段目标（`0x2680`）

| 字段 | 位 | 目标 | 语义（证据） |
|---|---|---|---|
| `b0` | bit7 | `0xFF2012.0 = 1`；并把 `0xFFAAC6` 高 4 位也设为 `b3` | 双 nibble 都为波段号；当前表无 `b0.7=1` 的项 |
| `b0` | bit6 | `0xFF20B6 = u32` | 仅 70 MHz 项（`b3=0x0B`）置位；把频段频率写入 `0xFF20B6` |
| `b0` | bit5 | `0xFF2070.7` | 模式标志 |
| `b0` | bit3 | `0xFF2070.4` | 模式标志（FM SQL THN / FM-N DEV 项为 1） |
| `b1` | bit3 | `0xFF206F.1` | 滤波/增益模式 |
| `b1` | bit2 | `0xFF206F.0` | 滤波/增益模式 |
| `b1` | bit1 | `0xFF2071.1` | 滤波/增益模式 |
| `b1` | bit0 | `0xFF2071.0` | 滤波/增益模式 |
| `b1` | 高 4 位 | 传入 `0x12980`（`r0l = b1 >> 4`） | 波段栈/显示组选择；`0x12980` 先调 `0x329D2`/`0x35A20`，再按高 4 位跳转 |
| `b2` | — | 不读 | 保留 |
| `b3` | 低 4 位 | `0xFFAAC6 = (old & 0xF0) | (b3 & 0x0F)` | **当前波段号** |
| `b4` | 低 4 位 | `0xFF206C = (old & 0xF0) | (b4 & 0x0F)` | 工作/校准模式 |
| `b5` | 低 3 位 | `0xFFAB23 = (old & 0xF8) | (b5 & 0x07)` | 子模式 |
| `u32` | — | `0xFF20B6`，仅当 `b0.6=1` | 频段频率（Hz，大端） |

### 2.2 `0x2680` 反汇编（关键行）

### 2.3 `0xA0C2` 的副作用

```text
a0c2: jsr 0xA1DA
a0c6: jsr 0xA0D4
a0ca: jsr 0xA7F0
a0ce: jsr 0xB9E2
a0d2: rts

a0d4: bset #4,@0xFF2013
a0dc: jsr 0x32E1E        ; 波段切换
a0e0: bclr #4,@0xFF2013
...
```

所以 `0x2680` 不只是“写几个 RAM 标志”：它会把当前波段切到 `b3` 对应的波段，并刷新显示。`SPN` 写 `N` 后立即调用 `0x1622 -> 0x2680`，因此**会改变当前波段/模式**。

## 3. 波段号 `b3`

`b3` 是低 4 位的波段索引，取值与频率的对应关系（全表统计）：

| `b3` | 频率（Hz） | 频率（MHz） | 备注 |
|---|---|---|---|
| `0x00` | 1,850,000 | 1.85 | |
| `0x01` | 3,570,000 | 3.57 | |
| `0x02` | — | — | **全表未使用**（5 MHz 不在服务校准项中） |
| `0x03` | 7,100,000 | 7.10 | |
| `0x04` | 10,100,000 | 10.10 | |
| `0x05` | 14,200,000 | 14.20 | |
| `0x06` | 18,100,000 | 18.10 | |
| `0x07` | 21,200,000 | 21.20 | |
| `0x08` | 24,900,000 | 24.90 | |
| `0x09` | 28,700,000 | 28.70 | |
| `0x0A` | 51,500,000 | 51.50 | |
| `0x0B` | 70,250,000 | 70.25 | 只有这些项带 `b0.6=1`，写入 `0xFF20B6` |

> 标签也互相印证：`2-035[M] FM GAIN S1 28` 的 `b3=0x09`（28.7 MHz），`2-036[M] FM GAIN S1 50` 的 `b3=0x0A`（51.5 MHz），`2-001[M] Local 7` / `2-002[M] Local 14` 分别为 `b3=0x03` / `0x05`。这说明 `b3` 是**该服务项进行校准/调整时使用的波段**，`u32` 是该波段的频率。

> `0x02` 空缺：按频段顺序（1.85 / 3.57 / ? / 7.1 …）**推测**它对应 5 MHz，但表中确实没有 5 MHz 校准项。这只是旁证；`SPN` 不能开 5 MHz 发射的直接原因是它不写 TS/EXP、也不改 TX 频段表 `0x32B2A`。

## 5. 25 字节标签表 `0x3324`

- 起始：`0x3324`
- 步长：`0x19`（25）字节
- 项数：294（`0x126`）
- 表尾：`0x3324 + 0x126*0x19 = 0x4FDA`；最后一项 `N=0x125` 位于 `0x4FC1–0x4FD9`，在镜像范围内。
- 编码：ASCII，右侧空格填充；每条包含服务菜单编号（如 `3-224`）和名称。

示例：

```text
N=0x110 @0x4DB4: "3-224[T]  FB GAIN 1.8"
N=0x111 @0x4DCD: "3-225[T]  FB GAIN 3.5"
N=0x11A @0x4EAE: "3-234[T]  FB GAIN 70"
N=0x11B @0x4EC7: "3-235[T]  CART LIMIT 1.8"
N=0x125 @0x4FC1: "3-245[T]  CART LIMIT 70"
```

完整 294 项见 [`服务菜单项目表.csv`](服务菜单项目表.csv)（列：`code_hex,code_dec,label,b0,b1,b2,b3_band,b4_mode,b5_sub,band_hz,band_mhz,item_ram,item_fram,apply_ram,apply_fram,apply_kind,grp,subgrp,grp_off`）。`item_*` 是每项 1 B 的基址；`apply_*` 是实际应用目标（`item` / `special_11` / `shared_54` / `meter_*`）。

> **显示号 ≠ `N`**：标签里的 `3-224` 是面板显示号，`N=0x110` 才是内部索引；两者偏移随组变化（组 3 的 `N=0x105–0x125` 对应显示 `3-213–3-245`，差 `0x30`；组 1/2 又不同）。不要用显示号直接写 `SPN`，以 `0x3324` 标签表/CSV 为准。

> **外部交叉验证**：Yaesu *FTDX10 Technical Supplement* 的 Alignment 表列出 `1-002 FAN`、`1-004 VCXO`、`1-005 Reserved 0` … `1-008 Reserved 3`、`2-027 FIL GAIN 0.3k` 等，与 `0x3324` 标签表中的编号/名称一致。这从官方资料侧支持 `0x3324` 是**服务菜单标签表**、`N` 是服务菜单项目号。

### 5.1 标签查找的 `-S` 规则

`0x376EA`（CAT/显示侧构造标签响应）：

```text
376ea: mov.b @0xFFAB02,r1l      ; S
376f6: mov.w @0xFFAB00,r0       ; N
376fc: extu.w r1
376fe: sub.w r1,r0              ; N - S
37700: bcc 0x37706
37702: add.w #0x126,r0          ; 回绕
37706: ...
3770c: mov.w #0x19,r1
37710: mulxu.w r0,er1           ; (N-S)*25
37712: add.l #0x3324,er1        ; 标签表
37718: mov.b #0x19,r0h
3771a: jsr 0x35AAC             ; 复制 25 B 到缓冲
```

所以 `S` 是**页内偏移/子码**，标签索引取 `N-S`（通常是该页/组的首项）。`0x35AAC` 的约定是 `r0h=长度`、`er1=源`、`er2=目的`。

`0x15C2`/`0x15F8`（服务菜单加/减）：

```text
15c2: btst #2,@0xFF2013
15ca: bne 0x15F8
15cc: r0 = @0xFFAB00
15d2: inc.w #1,r0
15d4: cmp.w #0x126,r0
15d8: bcs 0x15DE
15da: r0 = 0
15de: @0xFFAB00 = r0
15e4: r0l = @0xFFAB02
15ea: cmp.b #7,r0l
15ec: bcc 0x1622
15ee: inc r0l
15f0: @0xFFAB02 = r0l
15f6: bra 0x1622
15f8: ... 递减，0 回绕到 0x125；S 减到 0 为止
1622: jsr 0x2680
```

`0x15C2` 从 `0x15328` 的服务菜单动作表调用；`0x15F8` 是反向动作。

## 6. 校准值映射 `0x1FE2` 与 `0x1662`

### 6.1 `0x1FE2`：`N -> 0xFFA948 + N`

```text
1fe2: r0 = @0xFFAB00
1fe8: r4l = 0
1fea: r2 = r0
1fec: r3l = 0
1fee: cmp.w #0x8,r0 ; bcs 0x217E      ; N<8 -> 组0
... 逐段比较，r4l=组号，r3l=子组，r2=组内偏移 ...
217e: mov.w r0,r1
2180: extu.l er1
2182: add.l #0xFFA948,er1             ; 校准值地址
2188: rts
```

| 组 | `N` 范围 | 子组 `r3l` |
|---|---|---|
| `0x00` | `0x000–0x007` | 0 |
| `0x01` | `0x008–0x00C` | 0 |
| `0x02` | `0x00D–0x011` | 0 |
| `0x03` | `0x012–0x016` | 0 |
| `0x04` | `0x017–0x021` | **1** |
| `0x05` | `0x022–0x029` | 0 |
| `0x06` | `0x02A–0x02B` | 0 |
| `0x07` | `0x02C–0x030` | **2** |
| `0x08` | `0x031–0x039` | 0 |
| `0x09` | `0x03A–0x044` | 0 |
| `0x0A` | `0x045–0x053` | 3 |
| `0x0B` | `0x054–0x062` | 3 |
| `0x0C` | `0x063–0x071` | 3 |
| `0x0D` | `0x072–0x080` | 3 |
| `0x0E` | `0x081–0x08F` | 3 |
| `0x0F` | `0x090–0x09E` | 3 |
| `0x10` | `0x09F–0x0AD` | 3 |
| `0x11` | `0x0AE–0x0BC` | 3 |
| `0x12` | `0x0BD–0x0CB` | 3 |
| `0x13` | `0x0CC–0x0DA` | 3 |
| `0x14` | `0x0DB–0x0E6` | 3 |
| `0x15` | `0x0E7–0x0F1` | 0 |

| `0x19` | `0x105–0x125` | 0 |

> `0x1FE2` 的地址只用 `N`，`r4l/r3l/r2` 是给应用/显示用的分组元数据。

### 6.2 `0x1662`：对特定项应用校准值

`SPAET`（`0x2D38C`）调用 `0x1662`。关键分支：

```text
1662: jsr 0x1FE2
1666: cmp.w #0x0,r0 ; beq 0x1686      ; N=0x000 VDD MTR
166c: cmp.w #0xF2,r0 ; beq 0x1696     ; N=0x0F2 ALC MTR
1672: cmp.w #0x101,r0 ; beq 0x16AA    ; N=0x101 IDD MTR
1678: cmp.b #1,r3l ; beq 0x16B8       ; 子组1（N=0x017–0x021）
167c: cmp.b #2,r3l ; beq 0x16EC       ; 子组2（N=0x02C–0x030）
1682: andc #0xFE,ccr ; rts             ; 其它项：carry clear（不处理）
1686: @0xFFAAAF = @0xFF2428
1696: if 0x3D1B6()!=0: @0xFFAAB0 = @0xFF242F
16AA: @0xFFAAB1 = @0xFF2424
16B8: ... 写 0xFFAA6E + (N-0x17)，N=0x17/0x18 特判
16EC: @er1 = max(2, @0xFF2425)
```

结论：`0x1662` 不是“所有项目的统一写入”，而是对电源表、ALC 表、IDD 表及两个子组的专用应用逻辑。其它项由服务菜单自己的显示/写入路径处理。

### 6.3 `0x162E`：`r3l=3` 的 54 B 共享数组

`0x3BA1A` 在服务模式（`0xFF2020.7=1`）下先调 `0x162E`，再调 `0x1FE2`；当 `r3l==3` 时，`0x162E` 把当前测量值 `0xFF2432` 写到共享数组：

```text
162e: jsr 0x3D1B6
1632: bne 0x1660
1634: jsr 0x1FE2
1638: cmp.b #3,r3l ; bne 0x1660
163c: er1 = 0xFFAA79
1642: r0 = N
164c: r0 -= 0x45
1650: divxu.b #3 -> r0 = (N-0x45)/3
1656: er1 += r0
1658: r0l = @0xFF2432
165e: @er1 = r0l
```

即 `r3l=3` 的项（`N=0x045–0x0E6`，共 54 个 `FALC/MTR/TXG` 三元组）共享一个 54 B 数组：

| 项 | RAM | FRAM | 大小 |
|---|---|---|---|
| `r3l=3` 共享值 | `0xFFAA79 + (N-0x45)/3` | `0x013B + (N-0x45)/3` | 54 B |

- 每个 `FALC/MTR/TXG` 三元组（如 `0x045/0x046/0x047` = 100W 1.8 的 FALC/MTR/TXG）共用同一个槽。
- 只有 `0xFF23C4==5` 时 `0x162E` 才写入（`0x3D1B6` 返回非零则跳过）；`0xFF23C4` 的具体含义未定（可能是测量/发射状态）。
- 源 `0xFF2432` 是测量/计算值，具体物理量未定；这里只确认**寻址**。
- 这与 `0x1662` 的 `r3l=1/2` 路径不同：`0x162E` 是服务模式测量路径，`0x1662` 是 `SPAET` 的“应用默认/特殊值”路径。

371 B 块因此正好分区：

| 区域 | RAM | FRAM | 大小 | 用途 |
|---|---|---|---:|---|
| 每项 1 B（所有 `N` 都有） | `0xFFA948 + N` | `0x000A + N` | 294 | `r3l=0/2` 直接使用；`r3l=1/3` 另有专用/共享数组 |
| `r3l=1` 特殊组 | `0xFFAA6E + (N-0x17)` | `0x0130 + (N-0x17)` | 11 | `0x1662` 写入 |
| `r3l=3` 共享组 | `0xFFAA79 + (N-0x45)/3` | `0x013B + (N-0x45)/3` | 54 | `0x162E` 写入 |
| 表头 3 项 | `0xFFAAAF/0xFFAAB0/0xFFAAB1` | `0x0171/0x0172/0x0173` | 3 | VDD/ALC/IDD MTR |
| 其他 | `0xFFAAB2–0xFFAABA` | `0x0174–0x017C` | 9 | 其他设置 |
| **合计** | | | **371** | |

## 7. `SPN` 命令

`0x2D3C8`：

```text
2d3c8: btst #7,@0xFF2020 ; beq 0x27A5E   ; 必须服务模式
2d3d4: cmp.b #4,r3l ; bne 0x27A5E        ; 长度 4
2d3da: r2l = 0; r2h = 5
2d3de: er1 = 0xFF8A30
2d3e4: 累加 5 字节 -> r2l
2d3ec: r0l = @0xFF8A35
2d3f2: cmp.b r0l,r2l ; bne 0x27A5E      ; r2l(和) == 收到校验
2d3f8: r0 = (@0xFF8A33<<8)|@0xFF8A34     ; 两个数据字节
2d404: cmp.w #0xFFFF,r0 ; beq 0x2D420     ; 读
2d40a: cmp.w #0x126,r0 ; bcc 0x27A5E      ; 必须 < 0x126
2d412: @0xFFAB00 = r0
2d418: jsr 0x1622                        ; -> 0x2680
2d41c: bra 0x27A5A                        ; 回 A;
2d420: r0 = @0xFFAB00                     ; 读回
2d426: @0xFF8A33 = r0h
2d42c: @0xFF8A34 = r0l
```

因此：

- `SPN FFFF` 读当前项目号，回 **7 字节** `SPN<hi><lo><chk>;`（`0x2D420–0x2D454`），不是 `A;`。
- `SPN 0000–0125` 写项目号并**立即应用**（`0x1622 -> 0x2680`）。
- `SPN` 的校验和覆盖 `0xFF8A30–0xFF8A34` 共 5 字节，`0xFF8A35` 是收到的校验字节。
- 写成功后回 `A;`；门控失败/长度/校验/范围失败回 `?;`。

### 7.1 `SPN` 的实际影响

| 操作 | 影响 |
|---|---|
| `SPN 0114`（FB GAIN 14） | `N=0x114`，`b3=0x05` → 当前波段切到 14 MHz；`0xFF20B6` 不变（`b0.6=0`）；设 `0xFF206C` 低 4 位=1、`0xFFAB23` 低 3 位=6 |
| `SPN 011A`（FB GAIN 70） | `b3=0x0B`，`b0.6=1` → 当前波段切到 70 MHz，`0xFF20B6=70.25 MHz` |
| `SPN 011B`（CART LIMIT 1.8） | `b3=0x00` → 当前波段切到 1.8 MHz，模式=1，子模式=2 |
| `SPN 0000`（VDD MTR） | `b3=0x05` → 当前波段切到 14 MHz，子模式=3 |

> 这些是**服务校准项**。它们会改变当前波段/模式，但**不会**改变 `FRAM[0x0007]` 的 TS/EXP，也不会改变 `0x32B2A` 的 TX 频段表。
>
> `SPN` 只选择项目并应用 `b0–b5/u32` 的波段/模式标志；它**不写**该项目在 `0xFFA948+N` 的校准值。校准值由服务菜单的数值编辑、`SPw`/`SPr` 或 `SPAET` 处理。

## 8. 与 5 MHz 发射/TX 门闩的关系

- `SPN` 写 `0xFFAB00`；`0x2680` **直接**写 `0xFFAAC6`、`0xFF2070/206F/2071/206C`、`0xFFAB23`、`0xFF20B6`（后者仅 `b0.6=1`），并调用 `0xA0C2` 等波段切换/刷新例程。
- 它**不写**：
  - `FRAM[0x0007]` / `0xFF2007`（TS/EXP）；
  - `0x32B2A` 频段表；
  - `0xFF2014.5` 的频段检查结果（该位由 `0x3D1F2` 按频段表实时计算）。
- 因此 `SPN` **不能**把 5 MHz 加入 TX 频段表，也不能绕过 `0x3D0C2` 的 TX 硬门闩。
- 要开 5 MHz 发射，仍然是：`FRAM[0x0007]` 的 TS=2/3/7（或 EXP=1 / 服务模式 1.8–75 MHz 表），然后**整机断电重启**。
