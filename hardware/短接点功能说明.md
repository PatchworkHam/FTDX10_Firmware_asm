# FTDX10（MAIN V0115）短接点逐个功能说明

> 对象：`decoded/firmware/FTDX10_MAIN_V0115.bin`（**H8SX/1645** ＝ `R5F61645N50FPV`，512 KB Flash / 40 KB RAM / LQFP-144；本镜像覆盖其中**连续的 259,668 字节**：`0x000000–0x03F653`，长度 `0x3F654`）。
> 固件代码地址 = **文件偏移**；RAM/外设寄存器地址按 H8SX 运行时地址标注。文中每条结论都给了地址或字节，可自行复核（方法见 `可复现分析过程.md`）。
> 本镜像未读取的短接点，不排除由镜像外的出厂固件读取。

---

## 0. 一页结论

| # | 跳线 | 网络 | KR 线 | MCU 引脚 | 端口位 | 配置字节位 | 只焊这一个 | 本版固件**是否采用为配置** | 作用 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | JP1001 | TS0 | KR0 | 29 | PK0 | bit0 | `0x01` | 否（仅 A26 死路径） | 波段方案选择（低） |
| 2 | JP1002 | TS1 | KR1 | 28 | PK1 | bit1 | `0x02` | 否（仅 A26 死路径） | 波段方案选择（中） |
| 3 | JP1003 | TS2 | KR2 | 27 | PK2 | bit2 | `0x04` | 否（仅 A26 死路径） | 波段方案选择（高） |
| 4 | JP1004 | PWR0 | KR3 | 26 | PK3 | bit3 | `0x08` | **否** | 整机功率档（低） |
| 5 | JP1005 | PWR1 | KR4 | 24 | PK4 | bit4 | `0x10` | **否** | 整机功率档（高） |
| 6 | JP1006 | EXP | KR5 | 22 | PK5 | bit5 | `0x20` | **是（唯一现场重读的位）** | 频率覆盖/发射范围 |
| 7 | JP1007 | AUX0 | KR6 | 21 | PK6 | bit6 | `0x40` | **否**（且被强制清 0） | 未使用（保留） |
| 8 | JP1008 | AUX1 | KR7 | 20 | PK7 | bit7 | `0x80` | **否** | 未使用（保留） |

* 引脚 23 = VSS、25 = VCC，故编号在 22→24、24→26 处跳号。
* 配置字节值 = **已焊接点的按位或**。例：只焊 JP1004+JP1005 ⇒ `0x18`（= 100W 档）。
* **关键结论**：物理上 8 个点都在 KSC 列上，但本版固件里"把跳线写进配置字节"的那条通路是**死代码**；唯一活着的读法只取 **bit5（EXP）**。⇒ **跳线短接与否不影响功率档位**；本版固件中功率档来自 `FRAM[0x0007]`，跳线不参与。

## 1. 硬件通路

### 1.1 矩阵拓扑（原理图第 32 页）

```
                  KSC（共同阳极总线，由 MCU 驱动）
                   │
    ┌──────────────┼─────────────────────────────────────────┐
    │        D1018-2  D1019-1..3  D1020-1..3                 │
   (D1018 内 2 只 + D1019 3 只 + D1020 3 只 = 8 只二极管)
    │              │
    │        阴极 → 网络名（配置点）
    │           TS0  TS1  TS2  PWR0  PWR1  EXP  AUX0  AUX1
    │            │    │    │     │     │    │    │     │
    │         JP1001 JP1002 JP1003 JP1004 JP1005 JP1006 JP1007 JP1008  （焊接跳线）
    │            │    │    │     │     │    │    │     │
    └─────────── KR0  KR1  KR2  KR3   KR4  KR5  KR6   KR7  ──► MCU
```

* **只有 KSC 这一列（8 只二极管）是配置列。**
* D1017（IMN10 3 只）与 D1018-1 **不参与**配置：KS0/KS1/KS2/KS3 经它们送到 CNTL 板（KS-0..KS-3），属面板/PTT/按键信号链路。
* KR0–KR7 各有 4.7K 下拉（R1189–R1196 → GND）及 10K 串阻网络（RB1003 / RB1005，RAC104D103JCTP）接 MCU。KR0–KR6 经连接器同时引到 CNTL。

### 1.2 跳线 ↔ 网络 ↔ KR ↔ 引脚 ↔ 位

| 跳线 | 网络 | KR 线 | MCU 引脚 | H8SX 端口 | 配置字节位 |
|------|------|-------|----------|-----------|------------|
| JP1001 | TS0  | KR0 | 29 | PK0 | bit0 |
| JP1002 | TS1  | KR1 | 28 | PK1 | bit1 |
| JP1003 | TS2  | KR2 | 27 | PK2 | bit2 |
| JP1004 | PWR0 | KR3 | 26 | PK3 | bit3 |
| JP1005 | PWR1 | KR4 | 24 | PK4 | bit4 |
| JP1006 | EXP  | KR5 | 22 | PK5 | bit5 |
| JP1007 | AUX0 | KR6 | 21 | PK6 | bit6 |
| JP1008 | AUX1 | KR7 | 20 | PK7 | bit7 |

### 1.3 驱动侧与电气行为（0/1 极性）

* **KSC = MCU 引脚 116 = PC2**（原理图），经缓冲驱动 8 只二极管的阳极；**KSD = 引脚 117 = PC3**（与配置无关）。
* 端口 C 实际引脚（原理图）：PC0=45、PC1=46、**PC2=116**、**PC3=117**、PC4=47。
* KSC 拉高 → 二极管导通 → 若 JP 焊接，对应 KR 线被抬到 Vcc−0.6V（覆盖 4.7K 下拉）→ MCU 读到 **1**；KSC 拉低 → 截止 → 下拉到 **0**。

> **极性结论（无取反）**：`KRn = 1 ⇔ JPn 已焊接且 KSC 为高`。
> 即 **焊接/短接 = 1，断开 = 0**。固件侧没有任何取反：`0xA8A`（在 `0xA76` 末尾）直接 `mov.b @0xFFFBA3,r1l`，
> 经 `0xA60` 双读稳定后交 `0xA26`，`0xA26` 把 `r1l` **原样**写进 `0xFF2007`
> （死路径 `0xA26` 里 `r1h` 由 `0xA76` 开头的 `mov.w #0x0,r1` 保证恒 0；注意**实际** `0xFF2006` = FRAM[0x0006]，不等于恒 0）。

### 1.4 相关寄存器

| 名称 | 地址 | 固件中的写入（全镜像检索实测） | 作用 |
|------|------|------------------------------|------|
| **PORTK** | **0xFFFBA3** | 只读（`0xA8A`／`0xAC8`／`0xAE4`／`0x17364`，共 4 处） | 读 KR0–KR7（本机制的核心） |
| PKDR | 0xFFFBA7 | `0x12F6` 写 `0x00` | Port K 数据寄存器（输出值；本用途为输入，无影响） |
| **PCDR** | **0xFFFF5B** | `0x12E6` 写 0；`0x173F6` 改写低半字节 | 列选通，bit2 = PC2 = KSC |
| PJDR | 0xFFFBA6 | 共 30 处访问（`0x67E`/`0x12EE` 写、`0x35126`–`0x3F334` 的 `bset/bclr` 等；唯一一处 `mov` 写是 `0x12EE` 写 `0x02`） | Port J 数据寄存器（与配置无关） |
| PKDDR | 0xFFFBAB | **未见写入** | 方向寄存器（保持复位默认 = 输入） |
| PKICR | 0xFFFBAF | **未见写入** | 输入缓冲控制 |
| PKPCR | 0xFFFBBB | **未见写入** | 上拉 MOS 控制（默认关闭；板上有外部 4.7K 下拉） |
| PFCRD | 0xFFFBCD | **未见写入** | 端口功能控制 D：PCJKE 位使能 Port J/K。同块 `PFCR0/1/2/4/6/9/A/B/C` 由 `0x127E–0x12AE` 统一写 `0x00`，**唯独 PFCRD 不写** ⇒ J/K 使能只能来自镜像之外（见 §9 第 5 条） |
| PCDDR（Port C 方向） | 0xFFFB8B | **未见写入** | bits0–5 有效。全镜像对 `0xFFFB80–0xFFFB9E`（所有 `PnDDR`/`PnICR`）与 `0xFFFBA8–0xFFFBAB`（H–K 方向）**引用 0 处** ⇒ PC2 的输出方向同样来自镜像之外（见 §9 第 5 条） |

> 地址取自 H8SX/1645 寄存器表：手册写 `H'FFBA3`，即固件 24 位地址 `0xFFFBA3`（补一个前导 `F`）；
> `PCDR` = 手册 `H'FFF5B` → 固件 `0xFFFF5B`。上表「写入」列可用
> `python3 hardware/files/scripts/h8.py find "0xfffbab|0xfffbaf|0xfffbbb|0xfffbcd|0xffff5b"` 复现。

## 2. 固件里有哪几种"读短接点"的方式

### 2.1 列选通 —— 0x173F6（唯一的列号改写例程；初值由 0x12E6 写 0）

```
173f6: r0l = @0xFF23D7        ; 列号 0..4
173fc: r0h = @0xFFFF5B        ; PCDR
17402: r0h &= 0xF0
17404: r0l |= r0h
17406: @0xFFFF5B = r0l        ; 只改低半字节，高半字节保留
1740c: rts
```
低半字节位含义：bit0→PC0(45)、bit1→PC1(46)、**bit2→PC2 = KSC(116)**。
⇒ **列号 4（0b0100）恰好把 KSC 拉高**，这才是"读配置短接点"的那一列。

### 2.2 单次稳定读（配置列，列 4）

```
0xA76: 列号 0xFF23D7 := 4            ; 选 KSC
       调用 0x173F6 → PCDR = 4
       调用 0xA00（延时）
       r1l = @0xFFFBA3               ; 读 PORTK = 8 个短接点
       rts
0xA60: r2 = 0xFFFF
 loop: 调 0xA76 → r1
       若 r1 == r2 则 rts             ; 连续两次相同 → 稳定（双读防抖）
       r2 = r1，重试
0xA26: 调 0xA60 → @0xFF2006 = r1h（恒 0）、@0xFF2007 = r1l   ; ← "跳线 → 配置字节"
0xA38: 调 0xA60 → (cfg7 & 0x9F) | (跳线 bit5) → 0xFF2007     ; ← 只刷新 EXP
```
调用者统计：`jsr @0xA60` 全镜像只有 `0xA26`、`0xA38` 两处。

### 2.3 后台 5 列扫描器 —— 0x17358

```
17358: if (!0xFF2009.3) rts            ; 扫描使能
17364: r0l = @0xFFFBA3                 ; 读 PORTK（全 8 位）
17376: @(0xFF23F9 + 列号) = r0l        ; 按列号存本轮样本
1737e: 列号++ ; 若列号 != 4 → 0x173F6  ; 只循环列 0,1,2,3
       …把 0xFF23F9 与 0xFF23EE 比对：相同→置 0xFF200B.4"稳定"并把 0xFF23EE→0xFF23E3；不同→0xFF23F9→0xFF23EE
```
**注意：它只扫列 0–3，从不选列 4。** 列 0–3 对应 KS0–KS3（CNTL 面板/按键矩阵），
所以这个扫描器读到的是**面板信号**，不是配置短接点。
（细节：该例程**每次调用只处理一列**——列号存 `0xFF23D7`，先读 PORTK 存到 `0xFF23F9[列号]`，
再把列号 +1 并「跳入」`0x173F6` 选通（`bne 0x173F6` 实为尾跳转 + `rts`，返回到调用者）；
列号到 4 时不再选列，而是把 `0xFF23F9` 与 `0xFF23EE` 比 10 字节、置 `0xFF200B.4`、并把样本复制到 `0xFF23E3`。）
后续 `0x1740E` 把 `0xFF23E3` 当 one-hot 位图解成序号 → `0xFF23D2/0xFF23D0` → `0x1774C` 的跳表（302 项）派发：302 个条目指向 153 个不同目标，其中**按条目计有 102 项指向「首指令即 `rts`」的空处理例程**（若按唯一目标计，153 个里只有 2 个首指令是 `rts`，其余空处理例程带少量初始化前奏）；其余是机型参数初始化。

### 2.4 列 0/1 读 KR7 的 0xA92（**不是配置**）

```
0xAB6: 列号:=0 → 0x173F6 → 延时 → 若 PORTK.7=1 则 r1l.0=1
       列号:=1 → 0x173F6 → 延时 → 若 PORTK.7=1 则 r1l.1=1
       列号:=0 → 0x173F6（复原）
0xA92: 双读防抖 → @0xFF2001.0 / @0xFF2001.1
```
它只 `btst #7`（KR7）、只扫列 0/1，结果写 `0xFF2001` bit0/bit1
（读取者：`0x128A8`/`0x128B4`→`0xFF2386`、`0x1295A`/`0x1296A`、`0x2BDD4`、`0x33DAE`；另有 `0x2D186` 把整个字节镜像到 `0xFF8A36`）。
这是**同一条 KR7 线在别的列驱动下的面板按键语义**，与配置列（列 4）的 AUX1 **无关**，别混淆。

### 2.5 读 PORTK 的指令全集（全镜像只有 4 条）

| 地址 | 指令 | 所属例程 | 读到的位 | 可达性 |
|---|---|---|---|---|
| `0xA8A` | `mov.b @0xfffba3,r1l` | `0xA76`（列 4 = KSC） | 全 KR0–KR7 | 只被 `0xA60` 调；`0xA60` 只被 `0xA26`/`0xA38` 调 |
| `0xAC8` | `btst #7,@0xfffba3` | `0xA92`（列 0） | 仅 KR7 | 被 `0x830` 调（面板键，非配置） |
| `0xAE4` | `btst #7,@0xfffba3` | `0xA92`（列 1） | 仅 KR7 | 同上 |
| `0x17364` | `mov.b @0xfffba3,r0l` | `0x17358`（扫描，列 0–3） | 全 8 位 | 被 `0x139C`/`0x171C8` 调（面板矩阵） |

## 3. 逐个短接点功能说明

> 通用：位值定位 —— 全 8 位只在 `0xA8A`（配置列）与 `0x17364`（面板列）被读；
> 单个位在固件里的"证据指令"见下表各行。

### 3.1 JP1001 / KR0 / TS0（bit0）

* 电气：焊 ⇔ KR0=1 ⇔ 配置字节 bit0=1。
* 只有 `0xA8A` → `0xA60` → `0xA26` 这条会把它整字节写进配置，而 `0xA26` 是**死代码**；
  `0xA38` 也读同一列，但只采用 bit5（EXP），不采用 TS 位。
* 功能（TS 字段最低位）：与 TS1/TS2 一起选择**波段方案变体**。`0x1502` 只在 TS ∈ {0,2,3,6}（格雷码 000→010→011→110）时置“配置有效”标志 `0xFF204A.7`；`0x153A` 追加 `TS==1 && PWR!=0x10`。`{4,5,7}` 不置该标志，但 `0x32B10` 的频段表选择器仍按原始 TS 取表（详见 §6.1）。
* TS 的作用面：派生 `0xFF2008` 的 bit5/6/7 → 频段/频率上限常数（113/116/117/120/123/124/126/127/130）；选择 8 套业余波段边界表（`0x32B2A` 表）；选择波段位图并写 FRAM `0x55BB` 的 13 字节块；维护 `0xFF98A0` 功能允许位图（bit2–7 分段置位/清除）。
* **本机实效**：即使焊接，也不会改变功率；TS 值实际来自 FRAM[0x0007]。

### 3.2 JP1002 / KR1 / TS1（bit1）

* 同 3.1；是使 `TS=2/3/6` 成立的关键位（这三者都含 JP1002）。
* 附加：`0x153A` 里 `TS==1 && PWR!=0x10` 也算"配置有效"。

### 3.3 JP1003 / KR2 / TS2（bit2）

* 同 3.1；`TS∈{2,3,6}` 需它。`TS=6` 时 `0x3ABA0` 会把 TS 0↔6、3↔2 互换后再用。
* 频段表上 `TS=2` 是"宽 60m 5.25–5.4065 + 4m 70–70.5"的频段方案变体，`TS=3` 是"窄 60m 5.3515–5.3665"。

### 3.4 JP1004 / KR3 / PWR0（bit3）

* 电气：焊 ⇔ KR3=1 ⇔ 配置字节 bit3=1。
* **固件行为：PWR 位不被功率逻辑采用。** 全镜像里 `and.b #0x18`（掩 2 位字段的典型写法）共 **12 处**；
  其中**作用于配置字节 `0xFF2007` 的只有 7 处**（见 `../power/功率解锁方案.md` §1.1 的表），才是功率相关读者，
  而它们的输入是 `0xFF2007` 而非活着的 PORTK 读取；`0xFF2007` 的 bit3/4 来自 FRAM[0x0007]。
  另外 5 处作用于**别的变量**（`0xFFAB2B`：菜单设置打包字节；`*er1`：设置项步进器；状态/遥测路径），
  与功率上限无关（详见 `可复现分析过程.md` 的完整分类）。
* 语义（供参考，来自"若真被读会怎样"的表）：PWR 字段 = **整机功率档**：

| PWR(bit4:bit3) | 焊接组合 | 档位 | F/AC 默认（HF/50M/70M/AM） |
|---|---|---|---|
| `0x18` (11) | JP1004+JP1005 | 100 W | 100 / 100 / 50 / 25 |
| `0x00` (00) | 全不焊 | 50 W | 50 / 50 / 50 / 25 |
| `0x08` (01) | 只 JP1004 | 10–20 W | 10 / 20 / 20 / 20 |
| `0x10` (10) | 只 JP1005 | 10 W | 10 / 10 / 10 / 10 |

（4 项顺序对应 MAIN 内嵌字符串 `HF/50M/70M/AM MAX POWER`。）

### 3.5 JP1005 / KR4 / PWR1（bit4）

* 同 3.4。`0x18`（=100W 档）需要 JP1004+JP1005 都焊 —— 但**本版固件不看它**。
* 结论：**"100W 版短接点全空"与本版固件行为一致** —— 因为跳线根本不参与功率判定，
  100W 机与 50W 机的差异体现在 **FRAM 里的配置字节/功率默认值**，不是跳线。

### 3.6 JP1006 / KR5 / EXP（bit5）★ 唯一"活"的短接点

* 消费者（全镜像仅 2 处用 bit5）：
  * `0x32B06` `btst #5,@0xff2007` —— 频率范围表选择器 `0x32AEE` 内；
  * `0x27F62` `and.b #0x20,r0l` —— 出厂记录重组时**保留** EXP 位。
* **现场唯一会重读它的活路径**：`0xA38`
  ```
  a38: jsr @0xA60            ; 读配置列 → r1 = 0x00XX
  a42: r0l = @0xFF2007
  a48: and.w #0xFF9F,r0      ; 清 bit5、bit6
  a4c: and.w #0x20,r1        ; 只留跳线 bit5
  a50: or.w  r0,r1
  a58: mov.b r1l,@0xFF2007   ; 配置字节 = (原值 & 0x9F) | 跳线 EXP
  ```
  调用者只有 `0x8E54`（`0x8E50` 内），`0x8E50` ← `0x1570` ← `0x13D4`（设置版本不符）/`0x1446`。
  ⇒ 即只在"**恢复/初始化设置**"流程里，EXP 被跳线状态**覆盖**，同时 **AUX0(bit6) 被强制清 0**，而 TS/PWR/AUX1 保持 FRAM 原值。
* 作用：开关 `0x32B54` 表（1.8–30 MHz 连续 / 50–54 / 70–70.5）**替代** TS 选出的离散业余波段表 ⇒ 等价"宽频段发射"。与功率无关。
* **风险最小用法**：确需 EXP 就**短接 JP1006**（出厂做法，且能扛住 `0xA38` 的刷新）。
* **服务模式入口（已确认）**：CAT `ZZPE001000;` 把 `0xFF2002` 置 0 后软复位，`0x1438`→`0x1562` 置 `0xFF2020.7`；`ZZPE001001;` 触发 ALL RESET（`0x1446`→`0x1570`→`0x8E50`→`0x7EA2`，用默认表重写 400B 用户设置并应用 JP1006）。退出服务模式用 RESET 菜单（`0xDCBA` 清 `0xFF2020.7`）或整机断电重启；冷启动 `0x754` 不经过该检查。详见 `../TS/TS频段表与5MHz发射.md` §5.3。

### 3.7 JP1007 / KR6 / AUX0（bit6）

* **本版 MAIN 未使用**：全镜像不存在 `btst #6,@0xff2007`；且**把 `0xFF2007` 读进寄存器的 39 处中，没有任何一处随后掩 bit6**（完整表见 `可复现分析过程.md` §5.4）。孤立的 `and.b #0x40`（全镜像 5 处）经上下文核对均非配置字节（落在数据区/其它变量上）。
* 而且活路径 `0xA38` 会把 bit6 **强制清 0**。
* 只被整体拷贝到 FRAM / 工厂记录 / DISPLAY CPU。⇒ 纯保留位。

### 3.8 JP1008 / KR7 / AUX1（bit7）

* **本版 MAIN 未使用**（同 3.7：无 `btst #7,@0xff2007`，且 39 处读入中无一处掩 bit7；孤立的 `and.b #0x80`（全镜像 7 处）经上下文核对亦非配置字节）。
* 注意别与 `0xA92` 的"列 0/1 读 KR7"混淆 —— 那是面板按键矩阵（写 `0xFF2001`），不是配置位。

| 检查 | 结果 |
|---|---|
| 硬件（原理图 + 渲染图） | 8 只二极管共阳极 = KSC；阴极接 JP→KR；KR 有 4.7K 下拉 ⇒ 焊=1、断=0 |

## 5. 短接矩阵的 PWR/TS/AUX 位：**仅 EXP 被采用**

`0xA8A` 确实读取 `PORTK` 全部 8 位；但唯一活消费者 `0xA38` 只采用 bit5（EXP）。
下面先证明另一条"把整字节写回配置"的 `0xA26` 路径是死代码：

```
0xA26（跳线 → 0xFF2007）
  ← 0x7E9E  唯一调用者
      ← 0x7E8E（"出厂 FRAM 初始化"：写默认设置块 → 读跳线 → 写配置 → 全量初始化）
          ← 0x7D2E  唯一调用者
              ← 引用计数 = 0
```
对 `0x7D2E` 的三种独立扫描**全部为 0**：

| 扫描方式 | 命中 |
|---|---|
| 分支/调用目标为 `0x7D2E`（`bra/beq/bne/bcc/bsr/jsr/jmp`） | **0** |
| 反汇编文本中出现带 `0x` 前缀的 `0x7d2e` 引用 | **0** |
| 二进制中作为 32 位长字常量 `00 00 7D 2E`（跳转表项） | **0** |

> 一键复核：`python3 verify/verify_short_jumper.py`（A/B/C + `0xA26`/`0xA38`/`0xA58` 活路径断言）。

`0xA26` 还有 `0x7E9E` 的直接 `jsr`；它之所以是死代码，是因为唯一入口 `0x7D2E` 无引用。
`0xA58` **不是函数入口**，而是活函数 `0xA38` 的尾部写回（`0x1570 → 0x8E50 → 0x8E54 → 0xA38 → … → 0xA58`）。
它确实会执行，但只写回 `A38` 已掩码的结果；跳线的 bit3/bit4 仍未进入配置字节。
所以不能把 `0xA58` 当作死代码，也不能用“长字引用=0”作为通用死代码判据。
（对照：菜单处理 `0x15920`/`0x20DB4`/`0x20D80` 虽无 `jsr @imm` 调用者，但在跳转表里各有 1 处长字引用 —— 它们是**活的**；这只说明跳转表分派路径。）

**唯一活着的读法 `0xA38` 不采用跳线输入的 bit3/bit4**：掩码 `0xFF9F` 清 bit5/bit6，再用 `0x20` 只补 bit5。
⇒ 在本版固件中，PWR0/PWR1 即便短接，也不会被跳线改写；**跳线短接对功率没有影响**。

```bash
# 在仓库根目录执行
# 1) 确认"MOV.B @0xFFFBA3"全镜像只有 4 处（含 btst 形式见报告）

addrs = [0xfffb00+a for a in list(range(0x80,0x8f)) + list(range(0x90,0x9f))

print(sum(len(re.findall(re.escape(a.to_bytes(3,'big')), b)) for a in addrs))
```

## 9. 局限

1. 跳线↔网络↔KR 的对应、MCU 引脚号（PK0–PK7 = 29/28/27/26/24/22/21/20，PC2=116、PC3=117）均来自原理图目视 + 网络名顺序，置信度高但**未做实物验证**（用万用表在 KSC 拉高时量 KR 电平即可确认）。
2. 频率上限常数的单位未定（113/116/…/130，可能是频段表索引或某频段 MHz）。
3. `0xFF98A0` 位图各 bit 对应的具体"功能组"未落实到菜单文本。
4. 50W 版与 100W 版的**末级功放/驱动硬件是否相同**未验证（决定固件改完实际能出多少瓦）。
5. **端口方向/功能是"镜像外前提"（未证实）**：本镜像对全部 `PnDDR`（方向）、`PnICR`（输入缓冲）、`PFCRD`（PCJKE）**引用 0 处**——`0xFFFB80–0xFFFB9E`、`0xFFFBA8–0xFFFBAB`、`0xFFFBCD` 连地址字节都不出现。而手册规定：DDR 复位值在单芯片模式下为 `H'00`（输入），`PCJKE` 复位值为 0（**禁用 Port J/K**，且该位仅单芯片模式有效）。因此
   * "KSC = PC2，由 `PCDR`(0xFFFF5B) 驱动" 要求 `PCDDR.2 = 1`；
   * "读 KR0–KR7" 要求 `PCJKE = 1`（`PORTK` 属 J/K 组）。

   二者都不在本镜像内 ⇒ 只能由镜像之外的驻留程序（另一 MAT／出厂程序）设置。这与 §1.4 的 PFCRD 行"未见写入"一致，属**未证实前提**；不影响"跳线不参与功率判定"的结论（该结论依赖 `0xA26` 死路径，以及活路径 `0xA38` 只采用 bit5）。
6. 本机 CPU 为 `R5F61645N50FPV`（H8SX/1645）：Flash 512 KB，但本升级镜像只覆盖连续的 `0x000000–0x03F653`（259,668 字节，长度 `0x3F654`；16,230 条数据记录、0 处不连续）。高位空间不在镜像内，其内容（是否驻留引导程序）无法从本镜像判断 ⇒ "MAIN 无自写逻辑"只适用于镜像内这部分（0x0–0x3F653）。
