# `yaesu_ts_cat.py` 使用说明与修改点

> 脚本：`TS/yaesu_ts_cat.py`
> 参考实现：`/home/x3/下载/yaesu_power_cat.py`（同一套 `SPR/SPW` 二进制帧、同样的预览/`--apply`/回读校验风格）。
> 目标机型：FTDX10 MAIN V01-15（CAT `ID;` = `0761`）。

---

## 1. 它改什么

只改 **`FRAM[0x0007]`**：

| 位 | 字段 | 脚本行为 |
|---|---|---|
| bit0–2 | **TS** | `--ts 0..7` 改写 |
| bit3–4 | PWR | **保持原值** |
| bit5 | **EXP** | `--exp on/off/keep` |
| bit6–7 | AUX | **保持原值** |

写入公式：

```text
new = (old & 0xD8) | (ts & 0x07) | (exp ? 0x20 : 0)
```

即：

- 改 TS（保留 EXP）：`new = (old & 0xF8) | ts`。注意 EXP 优先级更高；EXP=1 时 TS 表不会生效。
- 改 TS 并确保 TS 表生效（清 EXP）：`new = (old & 0xD8) | ts`
- 开 EXP：`new = old | 0x20`
- 关 EXP：`new = old & 0xDF`
- 同时改：先清 bit0–2/bit5，再写入目标值；bit3/4/6/7 原样保留。

> 脚本默认 `--exp keep`：若当前 EXP=1，`--ts` 会保留 EXP 并打印警告；要让 TS 表生效，加 `--exp off`（例如 `--ts 2 --exp off --apply`）。

因为 `SPW` 一次写 2 字节，脚本读写的是 **`FRAM[0x0006]` + `FRAM[0x0007]`**；`FRAM[0x0006]` 原样写回。

> 若 `FRAM[0x0006]` 或校验和恰好是 `0x3B`（`;`），脚本会自动退回写 `FRAM[0x0007]` + `FRAM[0x0008]`，避免帧被截断；若两个窗口都含 `0x3B`，脚本会报错并拒绝发送。

## 3. 用法

### 3.1 离线查表（不连设备）

```bash
python3 TS/yaesu_ts_cat.py --table all
python3 TS/yaesu_ts_cat.py --table ts
python3 TS/yaesu_ts_cat.py --table exp
python3 TS/yaesu_ts_cat.py --table service
```

### 3.2 只读当前状态

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --read
```

输出示例：

```text
机型识别：FTDX10 MAIN V01-15 (CAT ID0761;)
FRAM[0x0006..0x0007] = 00 00
当前 TS=0，EXP=0，PWR=0x00（50 W）
当前覆盖（TS=0）：1.8-2 / 3.5-4 / 7-7.3 / ... / 50-54
```

### 3.3 预览（默认不写）

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --ts 2
```

会打印：

```text
目标：TS=2，EXP=0，PWR=0x00（保持不变），AUX=0x00（保持不变）
目标覆盖（TS=2）：1.81-2 / 3.5-3.8 / 5.25-5.4065 / ... / 70-70.5
FRAM[0x0007]: 0x00 -> 0x02
预览模式：确认无误后添加 --apply。
```

### 3.4 实际写入

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --ts 2 --apply
```

写入后自动回读：

```text
写入 0x0006 并回读验证成功；请整机断电重启后确认。
```

### 3.5 开/关 EXP

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --exp on  --apply
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --exp off --apply
```

### 3.6 同时改 TS + EXP

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --ts 2 --exp on --apply
```

注意：EXP=1 会覆盖 TS 表；此时 TS 值只在关掉 EXP 后才生效。

### 3.7 ID 未识别

```bash
python3 TS/yaesu_ts_cat.py -p /dev/ttyUSB0 --ts 2 --force
```

只有确认该机型使用相同 `FRAM[0x0007]` 布局时才用 `--force`。

## 4. 修改点（脚本文本里要改哪里）

如果你要移植/调整脚本，关键常量在文件顶部：

| 常量 | 当前值 | 含义 |
|---|---|---|
| `MODELS` | `{b"0761": "FTDX10 MAIN V01-15"}` | CAT `ID;` → 机型；新增机型先核实 |
| `CONFIG` | `0x0006` | 一次读写 2 字节的起始地址（TS 在第二字节） |
| `TS_MASK` | `0x07` | TS 位掩码 |
| `PWR_MASK` | `0x18` | PWR 位掩码（只用于显示/校验） |
| `EXP_BIT` | `0x20` | EXP 位 |
| `PWR_WATTS` | `{0x18:100, 0x00:50, 0x08:20, 0x10:10}` | PWR 编码 |
| `TS_TABLES` | 0–7 的 MHz 段 | 离线打印/预览用；改固件版本时同步更新 |
| `EXP_TABLE` | 1.8–30 / 50–54 / 70–70.5 | EXP 表 |
| `SERVICE_TABLE` | 1.8–75 | 服务模式表 |
| `TS_PRESETS` | 5 MHz 预设 | 仅展示，不写入 |
| `TS_VFO` | `{0:5.1675, 1:4.6300}` | 专用 VFO，仅展示 |

核心函数：

| 函数 | 作用 |
|---|---|
| `frame(cmd, addr, data)` | 生成 `SPR/SPW` 二进制帧 + 校验 + `;` |
| `Cat.read(addr)` | `SPR` 读 2 字节并校验回包 |
| `Cat.write_pair(addr, data)` | `SPW` 写 2 字节，要求回 `A;` |
| `safe_write_pair(cat, addr, data)` | 帧含 `0x3B` 时回退到 `addr+1` |
| `effective_table(ts, exp)` | 按优先级给出实际覆盖 |
| `print_tables(which)` | 离线打印 |

## 5. 目标 TS 速查

| 需求 | TS | 低 3 位 | 覆盖 |
|---|---:|---:|---|
| 5 MHz 最宽 + 4 m | 2 | `010` | 5.25–5.4065 + 70–70.5 + 50–52 |
| 窄 60 m + 最宽 HF | 7 | `111` | 5.3515–5.3665 + 1.8–30 + 50–54 |
| 窄 60 m 保守 | 3 | `011` | 5.3515–5.3665 + 50–52 |
| 默认/美版 5 MHz 预设 | 0 | `000` | 无 5 MHz 连续段；预设含 US 60 m 频道 |

## 6. 风险与注意

1. **必须断电重启**：`FRAM[0x0007]` 在上电时装入 `0xFF2007`；不要用 `ZZPE001001;` 代替——它等价于 **ALL RESET**（见第 7 条），会重写 400B 用户设置并应用 JP1006。
2. **EXP 会被跳线覆盖**：恢复/初始化设置的活路径 `0xA38`→`0xA58` 用 JP1006 覆盖 bit5。软改 EXP 在“恢复设置”后会丢失；想长期稳定就焊 JP1006。
3. **TS=4/5/7** 不在 `0x1502` 的常规有效集合 `{0,2,3,6}` 内；表仍存在，但不会置“配置有效”标志 `0xFF204A.7`。脚本会打印警告。
4. **TS=1** 需要 `PWR != 0x10` 才被 `0x153A` 接受；10 W 档下不满足。
5. **5 MHz 预设不会自动重写**：`0x8522` 只在恢复/初始化设置时执行；改 TS 只改频段表，不改已有 5 MHz 预设。
6. **TX 硬门闩已确认（MAIN 侧）**：TX 状态机 `0x3CC20` → `0x3D0C2` 直接调用 `0x3D1F2` 检查频段表；越界（carry clear）会清 `0xFFFBA4.2`，该位是 TX 序列/功率路径的允许位。`0xFF2014.5` 的极性是 **1=在频段内，0=越界**。因此 TS=2/3/7 在 MAIN 侧会通过门闩；若实机仍不能发射，再查 LPF/BPF、显示侧或 SUB 侧。
7. **服务模式入口已确认**：CAT 发 `ZZPE001000;` → `0xFF2002=0` → 软复位 → `0xFF2020.7=1`（1.8–75 MHz 表）。**不要用 `ZZPE001001;` 退出**：`0xFF2002=1` 走 `0x1446`→`0x1570`→`0x8E50`→`0x7EA2`→`0x8074`，用默认表 `0x82A6` 重写 `FRAM[0x0300]` 的 400B 用户设置块并应用 JP1006，等价于 **ALL RESET**。退出服务模式用 RESET 菜单（`0xDCBA` 清 `0xFF2020.7`）或整机断电重启。脚本暂不封装这条命令，需要时手动发送。
8. **服务模式副作用已确认**：入口 `0x1562` → `0x2680` 用**服务菜单项目编号** `0xFFAB00`（FRAM `0x0344`，0–0x125）索引 `0x27A8` 的 10 字节项目表，并调用 `0xA0C2` **切换当前波段/模式**。它改写 RAM `0xFFAAC6`（当前波段号）、`0xFF2070/206F/2071/206C`、`0xFFAB23`；`0xFF20B6` 仅在 `b0.6=1` 时写入（当前表只有 70 MHz 项，70.25 MHz）。`0x2680` 本身不写 FRAM；退出 `0xDCBA` 会保存 **371 B 内部设置** 到 FRAM `0x000A`、项目号到 `0x0344`、子码到 `0x0346`。进服务模式前至少备份 `FRAM[0x0000..0x0490]`；不要在服务模式里随意改项目号（隐藏 CAT `SPN`），它会切换波段。详见 [`../service_menu/README.md`](../service_menu/README.md)。

## 7. 实机验证清单

```text
[ ] 备份 FRAM[0x0000..0x0007]
[ ] 若进服务模式：先备份 FRAM[0x0000..0x0490]（至少 0x000A–0x017C、0x030A、0x0344、0x0346）
[ ] --read 记录当前 TS/EXP/PWR
[ ] --ts 2 预览，确认 FRAM[0x0007] 目标值只改了低 3 位
[ ] --apply 写入，回读一致
[ ] 整机断电重启
[ ] 调谐 5.3305 / 5.3515 / 5.3665 / 5.4035，确认能否发射
[ ] 检查 50 MHz 是否变为 50–52、70 MHz 是否出现（TS=2）
[ ] 检查 5 MHz 预设是否仍为原列表（TS=2 不应自动变 UK 7 频道，除非做过恢复设置）
[ ] 回滚：写回备份值，断电重启
```

## 8. 与参考脚本的差异

| 项 | `yaesu_power_cat.py` | `yaesu_ts_cat.py` |
|---|---|---|
| 目标位 | `FRAM[0x0007]` bit3–4（PWR） | bit0–2（TS）/ bit5（EXP） |
| 掩码 | `0x18` | `0x07` / `0x20` |
| 写入 | `(old & ~0x18) | watts` | `(old & ~0x27) | ts | exp` |
| 离线功能 | 无 | `--table` |
| 回退写 | 无 | `0x3B` 冲突时改写下一条 2 字节 |
| 额外警告 | 功率档编码未知 | TS 非正规值、TS=1+10W、EXP 覆盖、预设不自动重写 |
