# cat/ 结论与代码对照

> 目标固件：`../decoded/firmware/FTDX10_MAIN_V0115.bin`（MAIN，H8SX/1645 = `R5F61645N50FPV`）
> 反汇编依据：`../hardware/files/disasm/main_disasm.txt`（本项目中文件偏移 = 运行时地址）

## 0. 一页结论

### 0.1 未公开 CAT 命令

| 项 | 结论 |
|---|---|
| 固件命令表 | `0x27CF2`，**126 条**，每条 2 个 ASCII 字节 |
| 手册命令表 | **102 条**（含只在分命令章节出现的 `FT`，以及摘要表写作 `UL / UNLOCK` 的 `UL`） |
| 未公开命令 | **24 条**：`AN BG DP DS EK EO FD FK FR FS KC KT MK PE RO SY VF VT SP VE JP ZZ E0 E8` |
| 其中禁用桩 | **13 条**：`AN BG DP DS FK FR FS KC MK RO SY VF VT`；处理函数首 4 字节被改成跳错误，永远 `?;` |
| 其中有效逻辑 | **11 条**：`EK EO FD KT PE SP VE JP ZZ E0 E8` |
| 额外说明 | `UL` 也是桩，但它是手册里已有的命令，不计入“未公开 24 条” |

### 0.2 两条地址空间必须分清

| 命令 | 访问对象 | 地址范围 | 代码中的名字 |
|---|---|---|---|
| `SPW` / `SPR` | **外部 FRAM**（MB85RS256A，32 KB） | `0x0000–0x7FFF`，每次 2 字节 | `power/power_cat_optimized.py` 的主写路径；GUI 的“外部 FRAM” |
| `SPw` / `SPr` | **内部设置/校准表** `0xFFA948` | 表地址 `0x000A–0x017C`，每次 1 字节；`SPr 0xFFFF` 读 `0xFF2001` | GUI 的“设置/校准表” |

> 这是 `cat/` 中最容易被写反的一处：`SPW/SPR` **不是**内部 RAM，也不是 `0xFFA948` 设置表。

## 1. 固件命令表证据

### 1.1 表与解析器

| 证据 | 地址/值 | 复核结果 |
|---|---|---|
| ASCII 命令表 | `0x27CF2`，126 × 2 = 252 字节 | 126 条且互不相同；最后一条为 `E8` |
| 处理函数指针表 | `0x27AFA`，126 × 4 字节 | `0x27AFA + 126*4 == 0x27CF2` |
| 指针表前的内联上限 | `0x27AF8` | `0x007D` = 125（最大下标） |
| 解析器 1 | `0x27A0A` | 计数 `0x7E` = 126 |
| 解析器 2 | 第二套解析路径 | 计数 `0xFC` = 252；存在越界读取问题 |
| 桩判定 | 处理函数首 4 字节改为跳 `0x27A5E` | 13 条未公开桩 + 手册命令 `UL` |

`../verify/verify_hidden_cat.py` 会直接读固件字节并检查：
命令表数量/唯一性、指针表对齐、24 条隐藏命令集合、13 桩 + 11 有效、
解析器计数、`VE` 魔术串、`ZZ` 前缀/复位、`JP` 长度/不复位、
`E0/E8` 长度与源地址、`SPW` 长度/校验/阈值。当前离线复核结果为 **22/22 通过**。

### 1.2 11 条有效隐藏命令的入口

| 命令 | 入口 | 用途摘要 |
|---|---|---|
| `SP` | `0x2CF86` | 外部 FRAM / 内部设置表子协议，见下表 |
| `VE` | `0x2D4E8` | 版本/ID 查询，需 `VERAH076H`，回 48 字节 |
| `JP` | `0x27E7A` | 读写 `0xFF2006/07` 与 `0x2F0`×5 参数区；**不复位** |
| `ZZ` | `0x27DEE` | 校验 `PE0010` 后写 `0xFF2002`，`jmp 0x6EE` 软复位 |
| `E0` | `0x2D7C6` | 发送 229 字节诊断帧 |
| `E8` | `0x2D8D6` | 发送 10573 字节转储 |
| `FD` | `0x2982C` | 32 位频率/数据寄存器读写；读只接受通道 `0/1/2` |
| `KT` | `0x2A1EA` | CW 文本缓冲读余量/清空/追加，容量 30 |
| `EK` | `0x292A6` | 无参触发，调用 `0xDA00` |
| `PE` | `0x2B580` | 校准/调整参数读写，18 字节范围 `0xFFABD1..0xFFABE2` |
| `EO` | `0x29484` | 32 位偏移/微调 |

## 2. 启动、重载与版本检查

| 证据 | 结论 |
|---|---|
| `0x7D04` → `0x8F0C` | 开机从 FRAM `0x0006/0x0007` 读配置字节对，拆到 RAM `0xFF2007` 等 |
| `0x1502/0x153A` | 从 `0xFF2007` 拆 TS（bit0-2）与档位（bit3-4）；TS 有效集合为 `{0,2,3,6}`，`1` 仅在非 10W 档有效 |
| `0x7D4A` → `0x7E2E` | `SPW` 写入后重载设置块；F/AC 不需要断电即可刷新 |
| `0x13C2/0x13C6` | 开机设置 `r1=9` 并调用 FRAM 读原语读取 `FRAM[9]`，与固件 `0x3F650` 比较；不符调用 `0x1570` 触发设置重初始化 |
| `0x13D8/0x13E2` | 比较失败路径从固件内 `0x3F650` 取值，并调用 FRAM 写原语写回 `FRAM[9]` |
| `0x3F650` | 当前固件镜像字节为 `0x00`；**不能据此推断真机 `FRAM[9]` 必为 0** |

> 因此：档位 `FRAM[0x0007]` 需要断电重开才在 RAM/菜单生效；F/AC 由 `SPW` 写入后走重载路径。
> 脚本不检查也不写 `FRAM[9]`，但固件开机在版本不符时可能把它改写成 `0x00` 并重建配置；
> 这是脚本与固件两个层面的行为，不能混为一谈。

---


## 3. 未验证边界

1. **没有真机写入验证**：所有写命令、回读行为、断电重开后的效果都未在真实 FTDX10 上确认。
2. **没有确认真机 `FRAM[9]`**：只知道当前固件镜像 `0x3F650=0x00`；脚本只读记录。
3. **没有两台机对照数据**：50W 机的 `FRAM[7]` 出厂值是否恰好为 `0x00`、是否带其它 TS 位，仍未确认。
4. **隐藏命令是静态结论**：`JP`、`ZZ`、`PE`、`SPw/SPA*` 等写操作风险高，不能把“代码里能发”当成“真机安全”。

python3 verify/verify_hidden_cat.py

for p in ("power/power_cat_optimized.py", "cat/ftdx10_hidden_cat_gui.py"):
    compile(open(p, encoding="utf-8").read(), p, "exec")
PY
