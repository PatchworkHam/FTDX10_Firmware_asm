# FTDX10 未公开（隐藏）CAT 命令分析

> 目标固件：`decoded/firmware/FTDX10_MAIN_V0115.bin`（MAIN，H8SX/1645 = `R5F61645N50FPV`）
> 反汇编依据：`../hardware/files/disasm/main_disasm.txt`（文件偏移 = 运行时地址）
> 对照手册：`../original/manuals/dx10-cat.pdf`
> 结论日期：2026-10-17
>

## 1. 结论（TL;DR）

**存在未公开的 CAT 命令。**

- 固件里的 CAT 命令分派表共 **126** 条；CAT 手册的命令表共 **102** 条
  （含只在分命令章节出现的 `FT`，以及摘要表里写作 “UL / UNLOCK” 的 `UL`）。
- 因此有 **24 条命令代码出现在固件表中、但手册里没有**：

  ```
  AN BG DP DS EK EO FD FK FR FS KC KT MK PE RO SY VF VT SP VE JP ZZ E0 E8
  ```

- 这 24 条里：
  - **13 条是“禁用桩”**：处理函数只有一条 `bra 0x27a5e`，即永远回 `?;`。
    `AN BG DP DS FK FR FS KC MK RO SY VF VT`
  - **11 条有真实处理逻辑**（其中多条是维修/工厂/调试用途）：
    `EK EO FD KT PE SP VE JP ZZ E0 E8`

其中影响最大、最值得注意的几条：

| 命令 | 作用（概要） | 风险 |
|---|---|---|
| `SP` | **外部 FRAM / 内部设置表** 读、写（子命令 `SPW/SPR/SPw/SPr/SPM/SPN/SPA/SPS`），`SPARD` 可一次读出 371 字节内部设置表 | **高**（可改校准/配置） |
| `VE` | 版本/ID 查询，需魔术串 `VERAH076H`，回 `R ... DSP/ACPU/TFT/SDR ...;` | 低 |
| `JP` | 服务命令，需 `JP0010...`，读写 `0xFF2006/07` 并搬运 `0x2F0`×5 字节参数区（**不复位**） | 高（改启动/参数区） |
| `ZZ` | 服务命令，需 `ZZPE0010...`，写 `0xff2002` 后 **软复位** | 高（强制重启） |
| `E0` | 发送 229 字节带校验/掩码的诊断数据帧 | 中（只读） |
| `E8` | 发送 10573 字节（`0x294d`）二进制 **内存/数据转储** | 中（只读） |
| `FD` | 读/写一组 32 位频率/数据寄存器，并以 4 字节 BCD 返回 | 中 |
| `KT` | 写入 CW 文本缓冲（≤30 字符），置“文本就绪”标志 | 低 |
| `EK` | 无参数，调用 `0xda00`（与 `KT` 同一子系统） | 低 |
| `PE` | 参数/校准表按子命令读写（`0xffabd1..0xffabe2`），并写总线 | **高**（可改校准） |
| `EO` | 对 32 位偏移寄存器 `0xff20b6` 做 `+/-` 调整（值 < 1000） | 中 |

> 这些命令都能从普通 CAT 串口/USB 口进入：它们和手册命令共用同一张表和同一个解析器，
> 只是手册没有写出来。**请勿在正常使用中尝试 `SP`/`PE`/`JP`/`ZZ`，尤其是写操作**，
> 可能改动校准数据或导致设备重启/异常。
>
> 📖 **具体的串口设置、帧格式、每条命令的语法/校验/回包与示例，见 §7 详细使用说明。**

## 2. 固件证据链

### 2.1 命令表与处理函数表

| 结构 | 地址 | 说明 |
|---|---|---|
| ASCII 命令表 | `0x27CF2` | 126 条 × 2 字节，按字母序，止于 `0x27DED`（第 126 条 `E8`） |
| 处理函数指针表 | `0x27AFA` | 126 条 × 4 字节，大端 32 位地址；`0x27AFA` 前 2 字节 `0x007D`=125 是最大下标 |
| 表后紧邻 | `0x27DEE` | 命令表止于 `0x27DED`；紧接着 `0x27DEE` 就是 `ZZ` 处理函数入口，可佐证表长确为 126（末尾无填充） |

第 1 条是 `AB`（指针 `0x28136`），第 126 条是 `E8`（指针 `0x2D8D6`）。

### 2.2 解析与派发

- **接收 worker `0x27982`**：从队列取一条 100 字节记录（队列基址 `0xff8A97`，
  计数 `0xff8A95`，下标 `0xff8A96`，最多 30 条），把报文复制到 `0xff8A30`，
  并把“参数长度”写入 `0xff8A94`。
- **解析器 1 `0x27A0A`**：从 `0x27CF2` 起扫描 **`0x7E`=126** 条，
  用 `0xff8A30`/`0xff8A31` 两个字符匹配；命中后把下标写 `0xff36E0`，
  再调 `0x27AB2`。未命中走 `0x27A5E`，回 `?;`。
- **派发器 `0x27AB2` → `0x35A20`**：`0x35A20` 是一个带边界检查的内联跳转表
  （读表首的 `0x007D` 作为最大下标，取 4 字节指针后 `jmp @er1`）。
  进入处理函数时，`r3l` = `0xff8A94` = **参数个数**。
- **解析器 2 `0x2E00C`**：扫描同一张表 `0x27CF2`，但计数写成 **`0xFC`=252**。
  这是一个**固件小 bug**：表只有 126 条，多扫的 126 条会落到 `0x27DEE` 之后的
  `ZZ`/`JP` 处理代码里；不过派发器 `0x35A20` 的最大下标是 125，
  任何 ≥126 的假命中都会被拒绝，所以**不会产生新的有效命令**，只是浪费扫描。
  该解析器把结果写 `0xFF2706`，回复走 `0xFF28E0` 缓冲；解析器 1 回复走 `0xFF6089`。
  两者用 `0xFF202F` bit1 区分通道（两条 CAT 通道）。

### 2.3 “参数个数”约定

每个处理函数开头几乎都是：

```asm
cmp.b #<N>,r3l      ; r3l = 参数个数
bne   error         ; 不等于 N → 0x27A5E → 回 "?;"
```

- `N = 0` 表示“只读查询”（无参数）。
- 桩函数则是整条被替换成 `58 00 xx xx  bra 0x27A5E`（4 字节）。
- 有效回包结束前会写 `';'`，失败写 `'?' ';'`，另有 ACK 路径 `0x27A5A` 写 `'A' ';'`。

## 3. 24 条未公开命令逐条说明

### 3.1 禁用桩（13 条，永远 `?;`）

| 命令 | 处理地址 | 说明 |
|---|---|---|
| `AN` | `0x2831A` | 桩|
| `BG` | `0x28568` | 桩 |
| `DP` | `0x28F56` | 桩 |
| `DS` | `0x28F5A` | 桩 |
| `FK` | `0x29A28` | 桩 |
| `FR` | `0x29A74` | 桩 |
| `FS` | `0x29A78` | 桩 |
| `KC` | `0x29F6A` | 桩（同族的 `KM` 在 `0x29F6E` 正常） |
| `MK` | `0x2AAC2` | 桩（`ML` 在 `0x2AAC6` 正常） |
| `RO` | `0x2C06E` | 桩（`RS` 在 `0x2C072` 正常） |
| `SY` | `0x2CBC0` | 桩（`TS` 在 `0x2CBC4` 正常） |
| `VF` | `0x2CD4E` | 桩（`VG` 在 `0x2CD52` 正常） |
| `VT` | `0x2CE7A` | 桩（`VX` 在 `0x2CE88` 正常） |

这 13 条只是把原处理函数首 4 字节改成了跳错误，**功能已被刻意关闭**。
它们的存在本身说明：这些代码曾计划实现，后来被禁用（或属于别的机型）。

### 3.2 `SP` — 外部 FRAM / 内部设置表读写（0x2CF86）

`SP` 是隐藏命令里权限最高的一条，第三字符分派：

| 形式 | 入口 | 作用 |
|---|---|---|
| `SPW<addrHi><addrLo><d0><d1><chk>` | `0x2D016` | 向**外部 FRAM 地址** `addr`（2 字节大端，须 < `0x8000`；即 MB85RS256A 的 32 KB 空间）写 2 字节；`chk` = 前 7 个**原始字节**之和 & 0xFF |
| `SPR<addrHi><addrLo><chk>` | `0x2D076` | 从 `addr` 读回（返回 2 字节 + 校验 + `;`） |
| `SPw<addrHi><addrLo><pad><data><chk>` | `0x2D0E8` | 写设置表 `0xffA948 + (addr-0x0A)`，`addr` 须 `0x0A..0x17C` |
| `SPr<addrHi><addrLo><chk>` | `0x2D148` | 读设置表；`addr=0xFFFF` 时返回 `0xff2001` |
| `SPM T2` / `SPM TR` | `0x2D1E6` | `SPMTR` 调 `0x3B55A`（12B 数据，14B 帧）；`SPMT2` 调 `0x3B61C`（14B 数据，16B 帧）；仪表/温度类读数 |
| `SPN<hi><lo><chk>` | `0x2D3C8` | 存取 **服务菜单项目号** `0xffAB00`（0–0x125）；`0xFFFF` 为读回，否则须 < `0x126` 并调 `0x1622`（**需 `0xff2020` bit7**） |
| `SPA WE/RD/CL/ET` | `0x2CFBE` | 服务子命令分发：`SPARD` 一次返回 `0x173`=371 字节内部参数表；`SPAWE` 调 `0xDCBA`；`SPACL` 调 `0x7ED0`；`SPAET` 调 `0x1662`。均要求 `0xff2020` bit7 置位 |
| `SPS DR` | `0x2D458` | 调 `0x3E34E` 并读 `0xff98DE/DF`（SDR 相关） |

> 注意：`SP` 子命令的 `addr`/`data`/`chk` 都是**原始二进制字节**（**不是** ASCII 十六进制），
> 且 `SP` 帧不做大小写转换（所以 `SPW`/`SPw` 不同）。详见 §7.6。

`SPW/SPR` 底层用 `0xA528`（写原语）和 `0xA4A8`（读原语）；这两条就是固件读写外部 FRAM 的字节原语
（例：`0x8F0C` 读 `FRAM[0x0006/0x0007]` 配置字节对、`0x8F1E` 写回；`0x159B4` 把菜单设置写到 `FRAM[0x300+n]`）。
`SPw/SPr` 的地址空间是内部设置表 `0xFFA948`（`0x173`=371 字节），与 `SPW/SPR` 的 FRAM 空间**不是**一回事。
`SPARD` 把这张 371 字节表整块吐出，是**完整配置读取**。

> 例：写外部 FRAM 地址 `0x0123 = 0x45,0x67`：帧字节 `53 50 57 01 23 45 67 CA 3B`
> （`'S','P','W'`,0x01,0x23,0x45,0x67,校验 `0xCA`,`;`）。回 `A;`。

### 3.3 `VE` — 版本/ID 查询（0x2D4E8）

- 参数必须完整匹配 **7 字节魔术串 `RAH076H`**（`0xff8A32..0xff8A38` =
  `R A H 0 7 6 H`；完整帧为 `VERAH076H`，即 `VE` + 7 字节参数）。
- 命中后构造并返回一行 `R <6字符> DSP-xx-xx ACPU-xx-xx TFT-xx-xx SDR-xx-xx;`。
  6 字符来自 `0x3F63E..0x3F643`（若首字节为 `'V'`）或 `0x3F64A..0x3F64F`；
  `DSP/ACPU/TFT/SDR` 的数值来自 `0xFF98CC/CD`、`0xFF98D4/D5`、
  `0xFF98D0/D1`、`0xFF98D6/D7`，经 `0x35A42`（BCD 转换）和 `0x2D7BE`（hex→ASCII）。
- 这是**工厂/自检用的整机版本串**，比手册的 `ID` 命令信息更多。

### 3.4 `JP` — 服务命令（0x27E7A）

- 参数必须以 **`0010`** 开头（`0xff8A32..35` = `'0','0','1','0'`），
  且长度 `r3l` 为 **4** 或 **0xC**。
- 长度 `0xC`：把后 8 个十六进制字符解析成 2 个 16 位值（`r1`、`r2`），
  校验 `r1h^r2h == 0xFF`、`r1l^r2l == 0xFF`（即 `r2 == ~r1`），然后写 `0xFF2006`/`0xFF2007`，
  再 `jsr 0x8F1E`、`0xA5C2` 搬运 `0x2F0`×5 字节区；**末尾 `rts`（不复位）**。
- 长度 `4`：读 `0xFF2006/07` 及 `0xA4E2` 读回的 `0x2F0`×5 字节区，转成
  **25 字节**十六进制帧（`r0=0x19`）返回；**不复位**。
- 注：本节早期版本误写为“写寄存器后软复位”；复核代码后确认 **`JP` 不跳转 `0x6EE`**，
  真正触发重启的只有 `ZZ`（见 §3.5）。

### 3.5 `ZZ` — 服务命令 + 软复位（0x27DEE）

- 参数必须以 **`PE0010`** 开头，长度必须为 **8**。
- 取后 2 个十六进制字符（`0xff8A38/39`）解析成一个字节，调 `0x35B72`
  转换后要求结果 < 2，写入 `0xFF2002`，然后同样 `jmp @0x6EE`（软复位）。
- 与 `JP` 共用魔术前缀 `...0010`（写内部寄存器）；但**只有 `ZZ` 会 `jmp @0x6EE` 重启整机**。

### 3.6 `E0` — 229 字节诊断帧（0x2D7C6）

- 无参数检查，直接调用 `0x2D7EA` 在 `0xFF36E4` 处构造 **229（`0xE5`）字节**：
  - 以 `0xFF2397` 的值为“基值”（`r4l`），逐字节加上该基值做掩码；
  - 中间累加两个校验和（`r3h`、`r3l`，每 10 字节一组）；
  - 末尾追加 `;`。
- 再把 `0xFF36E2` 起的 229 字节经 `0x35AAC` 复制到 `0xFF6089`（CAT 发送缓冲），
  长度写 `0xFF36DC`，然后 `bra 0x27A96` 发送。
- 这是**带掩码/校验的二进制诊断数据帧**，不是文本。

### 3.7 `E8` — 10573 字节转储（0x2D8D6）

- 调用 `0x2D902` 在 `0xFF36E4` 构造帧头（基值固定为 `0x55`，同样带累加校验），
  然后把 `0xFF36E2` 起的 **`0x294D`=10573 字节**复制到 `0xFF6089` 并发送。
- 这是**大块二进制内存/数据区转储**，可一次吐出约 10 KB。

> `E0`/`E8` 都不校验参数长度，任何 `E0;` / `E8;` 都会触发。
> 两者都只读，但会占用 CAT 通道并回大量二进制数据。

### 3.8 `FD` — 32 位频率/数据寄存器读写（0x2982C）

- 写形式（长度 `0xC`）：前缀 `0020`，后 8 个十六进制字符拆成 4 字节，
  写入 `0xFF9898..0xFF989B`，再置 `0xFF2019` bit6/7、调 `0x1454A`、`0x8DB0`。
- 读形式（长度 `3`）：第 3 字符只接受 `'0'..'2'`，即 `0/1/2` **三个通道**。
  低半字节经跳转表（`0x35A20`，内联表在 `0x29924`，3 个入口）选择：
  通道 0 再按 `0xFF200D` bit6 在 `0xFF2358` / `0xFF22FA` 之间选择，
  通道 1 → `0xFF98A8`，通道 2 → `0xFF98AC`。
  随后写入 `0xFF230C`，调 `0x337CE`，再把 `0xFFA934..` 的值转成 BCD 输出。
- 从寄存器选择看，它读的是**频率/信道一类的 32 位数值**。

### 3.9 `KT` — CW 文本缓冲写入（0x2A1EA）

- 先调 `0x2A328` 做前置检查；然后：
  - `r3l=0`：读回（计算 `0x1E - 0xFF255A`，即剩余可用字符数，经 `0x35A42` 转十进制后返回）；
  - `r3l=1`：第 3 字符须为 `'0'`，置 `0xFF203D` bit1；
  - 其它：第 3 字符须为 `'1'`，把后续字符写入 `0xFF253B` 开始的缓冲区，
    长度计数 `0xFF255A`、位置 `0xFF255B`；固件在 `0x2A224` 另做字符范围校验；
    缓冲上限 `0x1E`=30，环形回绕；写完置 `0xFF203D` bit0，并令 `0xFF2485=1`。
- 结合 `0xFF253B/0xFF255A` 的用法，这是**CW 消息（keyer text）缓冲**。

### 3.10 `EK` — 触发 0xDA00（0x292A6）

```asm
cmp.b #0x0,r3l
bne   error
jsr   @0xDA00
rts
```

- 无参数，唯一动作是调用 `0xDA00`。
- `0xDA00` 检查 `0xFF204A` bit7、`0xFF203D` bit0/5、`0xFF2047` bit1 等，
  与 `KT` 使用的 `0xFF203D` 是同一子系统，推测是**应用/执行刚写入的 CW 文本**
  （或同族的“键控/消息”动作）。

### 3.11 `PE` — 参数/校准表读写（0x2B580）

- 长度 `3` 走 `0x2B842` 分支；长度 `6` 走主分支。
- 第 3~5 个参数字符为 `0/1/2` 的组合，按组合选择 `0xFFABD1..0xFFABE2`
  中的某个参数字节（例如 `0/1/2` 分别对应不同的子表与位域）；
  用 `0x35B76` 把 ASCII 十六进制转成二进制，写回表项，再经 `0xA528` 写总线，
  并置 `0xFF2029` bit4、`0xFF200E` bit7。
- 结构上就是**按索引读写一组校准/参数字节**（`PE` 很可能是 “Parameter EEPROM”）。

### 3.12 `EO` — 32 位偏移调整（0x29484）

- 长度必须为 `6`：`<0..2><+|-><0..2><3 位十六进制>`。
- 3 位十六进制先解析成 `0..999`，再按第 3 个参数位换算倍率：
  `0`→×1，`1`→×1000，`2`→×1,000,000（并检查高位不溢出）。
- 再取 `0xFF20B6` 的 32 位值：
  - 第 2 字符 `'+'` → 加；否则 → 减；
  - 写回 `0xFF20B6`，置 `0xFF2013` bit4，调 `0x32E1E`、`0xAA78`、`0xA6CE` 等。
- 即**对一个 32 位偏移/微调寄存器做带符号增减**（值上限 1000 量级）。

# 3) 反汇编：解析器 / 派发器 / 若干隐藏处理函数

## 7. 未公开命令 —— 详细使用说明

> 本节给出**可直接照抄**的操作方法：串口设置、帧格式、每条命令的精确语法 / 校验 / 回包，
> 以及示例与校验和计算。所有语法均来自对 `decoded/firmware/FTDX10_MAIN_V0115.bin` 处理函数的
> 反汇编（已在括号中标注地址）。
>
> ⚠️ **先读 §7.7 安全与风险**：`SP`/`PE`/`JP` 会写校准或启动参数，`ZZ` 会立即复位。

### 7.1 连接与串口参数

| 项目 | 取值 |
|---|---|
| 端口 | USB 虚拟串口的 **Enhanced COM Port**（CAT 用），或后板 **RS-232C** |
| 波特率 | 菜单 **08 CAT RATE**，出厂默认 **9600**（0=4800 / 1=9600 / 2=19200 / 3=38400）；菜单 06 232C RATE 同理 |
| 帧格式 | 8 数据位、无校验、1 停止位（8N1）、无流控（Yaesu CAT 惯例） |
| 超时 | 菜单 09 CAT TIME OUT TIMER，默认 100 ms |

### 7.2 帧格式与解析规则（关键）

- 一帧 = `<2 字母命令><参数...>;`，以 `;`（0x3B）结束；设备按 `;` 切帧。
- 命令表在 `0x27CF2`（126 条 × 2 字节），解析器 `0x27A0A` **只比较前 2 个字符**。
- **参数长度** `r3l` = 2 字母命令之后的字节数，由各处理函数逐一校验（见下）。
- **大小写规则**：接收时默认把英文字母**大写化**；但以 `SP` 或 `EM` 开头的帧**不做大写化**
  （`0x2DB22`/`0x2DB32`/`0x2DC2A`）。
  → 所以 `SPW` 与 `SPw`、`SPR` 与 `SPr` 是**不同**子命令，必须严格区分大小写；
    其余命令（如 `ve`）大小写不敏感。
- **回包**：
  - `A;`（0x41 0x3B）= 成功 ACK（`0x27A5A`）；
  - `?;`（0x3F 0x3B）= 失败 / 参数错（`0x27A5E`）；
  - 数据帧 = `<回显命令><数据><校验?><;>`（逐条见下）；
  - **有个别命令成功时在代码里不回包**（如 `EO`、`EK`、`KT` 写入分支、`PE` 写入分支、
    `FD` 写入分支）；该行为来自静态逆向，需真机确认。
- 队列 / 长度：设备最多缓存 **30** 条帧，单帧拷贝上限 **99 字节**，请勿超长。

### 7.3 快速上手代码

```python
import serial, time

def open_cat(port, baud=9600):
    return serial.Serial(port, baud, bytesize=8, parity='N',
                         stopbits=1, timeout=1)

def send_ascii(ser, s: str, wait=0.15):
    """ 发 ASCII 命令；s 不含结尾 ';'，本函数自动补 ';'。"""
    ser.reset_input_buffer()
    ser.write((s + ';').encode('ascii'))
    time.sleep(wait)
    return ser.read(8192)

def send_raw(ser, payload: bytes, wait=0.15):
    """ 发二进制帧（SP 子协议用）；payload 不含结尾 ';'，自动补 ';'。"""
    ser.reset_input_buffer()
    ser.write(payload + b';')
    time.sleep(wait)
    return ser.read(8192)

def echo(ser, s):
    r = send_ascii(ser, s)
    print(f'-> {s!r}   <- {r!r}')
    return r
```

> 用 `repr()` 显示回包，便于观察 `\x00`、`\xff` 等不可见字节。

### 7.5 逐条说明

#### 7.5.1 `VE` —— 版本查询（只读）

- **语法**：`VERAH076H`（参数正好 `RAH076H` 7 字节；`0x2D4E8` 逐字节比较）。
- **回包 48 字节**：
  `VER ` + `<机型/日期串 6>` + ` DSP-<cc><dd> ACPU-<ee><ff> TFT-<gg><hh> SDR-<ii><jj>;`
  尖括号为 2 位十六进制（A–F 由 `0x2D7BE` 以 `+7` 生成）。6 字节串取自 ROM `0x3F63E` 或 `0x3F64A`。
- **示例**：
  ```python
  echo(ser, 'VERAH076H')
  # -> 'VERAH076H'
  # <- b'VER 1234AB DSP-0102 ACPU-0304 TFT-0506 SDR-0708;'   (数字以真机为准)
  ```
- 说明：`RAH076H` 是硬编码“口令”，不属于常规 CAT。

#### 7.5.2 `FD` —— 内部寄存器读写

- **读**：`FD00<X>`，`X` ∈ `0`/`1`/`2`（3 参数，`0x29918`）。
  - `X`=0 时按 `0xFF200D` bit6 在 `0xFF2358` / `0xFF22FA` 中选择；
    `X`=1 取 `0xFF98A8`，`X`=2 取 `0xFF98AC`。
  - 回包 **15 字节**：`FD00<X>0<8 hex>;`
  ```python
  echo(ser, 'FD000')     # <- b'FD0000xxxxxxxx;'
  ```
- **写**：`FD0020<8 hex>`（12 参数）。8 个十六进制解成 **4 字节**写入 `0xFF9898..9B`，
  再调用 `0x1454A`；**成功无回包**（`0x29916` `rts`）。
  ```python
  echo(ser, 'FD002000011234')   # <- b''（无回包）
  ```
- 语义推断：内部调试寄存器 / 参数；写路径会置位 `0xFF2019` 相关位。

#### 7.5.3 `KT` —— CW 文本缓冲（键控存储器）

- 缓冲：`0xFF253B`，容量 **30**；`0xFF255A`=已用长度，`0xFF255B`=写指针。
- **读余量**：`KT`（0 参数）。回包 **6 字节**（`0x2A2C4`）：
  `KT` + `<保留字节>` + `<2 hex 剩余空间>` + `;`
  （第 3 字节是缓冲里的陈旧字节，属固件小瑕疵，可忽略）。
- **清空**：`KT0`（1 参数）。若 `0xFF203D` bit0 已置则置 bit1；**无回包**。
- **追加文本**：`KT1<文本>`（≥2 参数，文本长度 = `r3l-1`）。追加后总长 ≤ 30；
  固件在 `0x2A224` 按自己的范围校验字符（静态看为 `0x20–0x5F` 或 `0x7D`；CAT 默认
  会把字母大写化，所以小写字母通常以大写形式通过）。非法字符回 `?;`；成功无回包，
  `0x2A288` 置 `0xFF203D` bit0。注意 `0x3B`（`;`）虽在固件允许集合内，但它是 CAT 帧尾，
  实际不能出现在文本中；GUI 会在本地拒绝。
  ```python
  echo(ser, 'KT')              # <- b'KT\x00..\x1e;'   （剩余=30=0x1E）
  echo(ser, 'KT1HELLO WORLD')  # <- b''（无回包）
  echo(ser, 'KT0')             # <- b''（清空）
  ```

#### 7.5.4 `EK` —— 无参触发

- **语法**：`EK`（参数长度必须为 0；`0x292A6`）。
- 行为：调用 `0xDA00`（与 `KT` 同属 `0xFF203D` 子系统）；**无回包**。
  ```python
  echo(ser, 'EK')   # <- b''
  ```

#### 7.5.5 `EO` —— 偏移 / 微调

- **语法**：`EO<a><sign><b><ddd>`（**6 参数**，`0x29484`）：
  - `a` ∈ `0`/`1`/`2`：作用对象（0→`0xA790` 路径，1→`0xA79C` 路径，2→两者）；
  - `sign` = `+` 或 `-`：加 / 减；
  - `b` ∈ `0`/`1`/`2`：步进标度（×1 / ×1000 / ×1000000）；
  - `ddd` = 3 位十进制 `000`–`999`。
- 结果累加到 32 位单元 `0xFF20B6`，并置 `0xFF2013` bit4。成功**无回包**，非法回 `?;`。
  ```python
  echo(ser, 'EO0+0123')   # <- b''（对象0，+，×1，123）
  echo(ser, 'EO2-0010')   # <- b''（对象2，-，×1，10）
  ```

#### 7.5.6 `PE` —— 校准 / 参数字节读写

- **读**：`PE<3 选择位>`（3 参数，`0x2B842`），如 `PE000`。三元组 (s0,s1,mode) 各取 `0/1/2`，
  映射到 18 字节范围 `0xFFABD1..0xFFABE2`。
  - 回包 **9 字节**：`PE<s0><s1><m><sign><2 hex>;`，`sign` ∈ {`0`,`+`,`-`}（负数以补码读取）。
  ```python
  echo(ser, 'PE000')   # <- b'PE000+0A;'（示例）
  echo(ser, 'PE100')
  echo(ser, 'PE200')
  ```
- **写**：`PE<s0><s1><m><sym><2 hex>`（6 参数，`0x2B580`）。写同区并置 `0xFF2029` bit4；
  **成功无回包**。
  ```python
  echo(ser, 'PE000+0A')   # <- b''
  ```
- 说明：`PE` 直接读写**校准 / 调整参数**，误写会影响机器指标。

#### 7.5.7 `E0` / `E8` —— 内部二进制取数

- `E0`（`0x2D7C6`）：发送 **229（0xE5）字节**的掩码 / 校验帧（源基址 `0xFF2397`）。
- `E8`（`0x2D8D6`）：发送 **10573（0x294D）字节**（源 `0xFF36E2` → 目标 `0xFF6089`）。
- 两条**不校验参数**；回包是**二进制**（不是 ASCII），需按长度读取。
  ```python
  r = send_ascii(ser, 'E8'); print(len(r))   # ~10573
  ```

#### 7.5.8 `JP` —— 启动 / 参数区读写

- **读**：`JP0010`（4 参数）→ 回 **25 字节**（`r0=0x19`）：`JP0010` + 8 hex（`0xFF2006/07` 及其按位取反）
  + 8 hex + 2 hex（`0xA4E2` 读回的 `0x2F0`×5 区前 5 字节）+ `;`。
- **写**：`JP0010<8 hex>`（12 参数）。8 个十六进制分成两个 16 位字 v 与 w，
  **必须满足 `v ^ w == 0xFFFF`**（即 w 是 v 的按位取反，`0x27F3A`）；随后写
  `0xFF2006`/`0xFF2007` 并搬运 `0x2F0`×5 字节（`0xA5C2`）。**成功无回包**。
  ```python
  echo(ser, 'JP0010')             # 读
  echo(ser, 'JP00101234EDCB')     # 写 v=0x1234, w=0xEDCB (互补)
  ```
- ⚠️ 涉及启动参数 / 内部搬运，误用可能无法开机。

#### 7.5.9 `ZZ` —— 服务模式开关 / 复位

- **语法**：`ZZPE0010<2 dec>`（8 参数，`0x27DEE`）；`<2 dec>` 必须是十进制 `00` 或 `01`（`0x282A6` 只接受 `'0'`–`'9'`，`0x35B72` 做 BCD→二进制，结果必须 `< 2`）。
- 写 `0xFF2002` 后 `jmp 0x6EE`（软复位，栈设 `0xFFC000`）。**立即重启，无回包**。
  ```python
  send_ascii(ser, 'ZZPE001000')   # 0xFF2002=0 → 服务模式（0xFF2020.7=1）
  send_ascii(ser, 'ZZPE001001')   # 0xFF2002=1 → ALL RESET（重写 400B 用户设置）
  ```
- 服务模式会启用 `SPN`/`SPA*` 门控、把频段表切到 `0x32B4A`（1.8–75 MHz）、并改变功率钳位；退出用 RESET 菜单（`0xDCBA` 清 `0xFF2020.7`）或整机断电。
- **入口副作用**：`0x1562` → `0x2680` 用服务菜单项目号 `0xFFAB00`（FRAM `0x0344`）索引 `0x27A8` 的 10 B 项目表，并调用 `0xA0C2` **切换当前波段/模式**；`0x2680` 本身不写 FRAM。退出 `0xDCBA` 保存 371 B 内部设置到 `0x000A`、项目号到 `0x0344`、子码到 `0x0346`。
- ⚠️ **不要用 `ZZPE001001;` 退出服务模式**：它走 `0x1446`→`0x1570`→`0x8E50`→`0x7EA2`→`0x8074`，用默认表 `0x82A6` 重写 `FRAM[0x0300]` 的 400B 用户设置，并用 JP1006 覆盖 EXP，等价于 ALL RESET。冷启动（`0x754`）不执行该检查。

### 7.6 `SP` 二进制子协议（重点）

`SP` 是**二进制**子协议：`SP` 之后的字节按**原始二进制**解释（**不是** ASCII 十六进制），
校验和 = **原始字节之和 & 0xFF**，作为一个**原始字节**发送。因 `SP` 帧不做大写化，子命令区分大小写。

**帧布局**：`'S' 'P' <子命令字节/参数...> <校验字节>`，最后跟 `;`。
（校验字节 = `('S'+'P'+其后所有字节) & 0xFF`）

> ⚠️ 二进制校验字节**可能等于 `0x3B`（`;`）**而被设备当作帧尾；参数里也应避免出现 `0x3B`。
> 若遇到异常，请更换参数，必要时再做真机确认。

子命令（首字节 = `0xFF8A32`，`0x2CF86` 分派）：

| 子命令 | 语法（除首字节外均为原始字节） | 参数长度 | 回包 |
|---|---|---|---|
| `W` | `SPW <addrHi> <addrLo> <d0> <d1> <chk>` | 6 | `A;` |
| `R` | `SPR <addrHi> <addrLo> <chk>` | 4 | `SPR<addrHi><addrLo><d0><d1><chk>;`（9B） |
| `w` | `SPw <addrHi> <addrLo> <pad> <data> <chk>` | 6 | `A;` |
| `r` | `SPr <addrHi> <addrLo> <chk>` | 4 | `SPr<addrHi><addrLo><00><data><chk>;`（9B） |
| `M` | `SPMTR <chk>` 或 `SPMT2 <chk>` | 4 | 14B / 16B 帧（数据 12B / 14B） |
| `N` | `SPN <hi> <lo> <chk>`（写）；读时 `<hi><lo>` = `FF FF` | 4 | 写：`A;`；读：`SPN<hi><lo><chk>;`（7B） |
| `A` | `SPAWE` / `SPARD` / `SPACL` / `SPAET` `<chk>` | 4 | 见下 |
| `S` | `SPSDR <b0> <b1> <chk>` | 6 | 9B 数据帧 |

> **门控**：`SPN` 与 `SPA*` 需要 `0xFF2020` bit7 = 1（扩展/维修模式），否则一律回 `?;`；
> `SPW` / `SPR` / `SPw` / `SPr` / `SPM` / `SPSDR` **无**此门控。

逐条：

- **SPW**（写外部 FRAM `0x0000–0x7FFF` 的 2 字节）：`addr=(addrHi<<8)|addrLo` 必须 `< 0x8000`。
  d0→addr、d1→addr+1（写原语 `0xA528` 会自动 `addr++`）。
  校验 = `('S'+'P'+'W'+addrHi+addrLo+d0+d1) & 0xFF`。
  例：写 0x0123 = 0x45,0x67 → 字节 `53 50 57 01 23 45 67 CA`，再跟 `;`。
- **SPR**（读 2 字节）：addr 必须 `< 0x8000`。回包回显请求前 5 字节后接 `d0 d1 chk ;`。
  例：读 0x0100 → 发送 `53 50 52 01 00 F6` + `;`。
- **SPw**（写设置表）：`addr` ∈ `0x000A–0x017C`，写入 `0xFFA948 + (addr-0x0A)`；
  校验 = `('S'+'P'+'w'+addrHi+addrLo+pad+data)&0xFF`（`pad` 参与校验但不使用）。
- **SPr**（读设置表）：`addr`=`0xFFFF`→读 `0xFF2001`；`0x000A–0x017C`→读设置表。
  回包含一个 `0x00` 保留字节（原校验位被清零）。
- **SPM**：`SPMTR`→14 字节；`SPMT2`→16 字节（调用 `0x3B55A` / `0x3B61C` 取读数）。
  校验 = 前 5 字节之和。
- **SPN**（**需 `0xFF2020` bit7 = 1**，否则回 `?;`）：把 `<hi>:<lo>` 当作 16 位数：`0xFFFF`=读 `0xFFAB00`；
  `< 0x0126`=写 `0xFFAB00` 并调用 `0x1622`；其它值回 `?;`。
  `0xFFAB00` 是**服务菜单项目编号** `N`（0–0x125）；`0x2680` 用 `N*10` 索引
  `0x27A8` 的 10 字节项目表，并调用 `0xA0C2` **切换当前波段/模式**。并行标签表在 `0x3324`
  （294 × 25 B）：`0x110–0x11A` = `FB GAIN 1.8…70`，`0x11B–0x125` = `CART LIMIT 1.8…70`。
  详见 [`../service_menu/README.md`](../service_menu/README.md)。
- **SPA**（**需 `0xFF2020` bit7 = 1**，否则回 `?;`）：
  - `SPAWE` → 调用 `0xDCBA`（写使能），回 `A;`
  - `SPARD` → 回 **378（0x17A）字节**：回显 5 字节 + 371 字节设置表 `0xFFA948` + 校验 + `;`
    （`0x2D2D2`，经 `0xFF6089` 缓冲发送）
  - `SPACL` → 清（`0x7ED0`），回 `A;`
  - `SPAET` → 调用 `0x1662`，成功回 `A;` 否则 `?;`（仅 `0x1662` 支持的表头/`r3l=1/2` 特殊项会成功；普通项回 `?;`）
- **SPSDR**：`<b0>:<b1>` 组成字，调用 `0x3E34E` 并轮询 `0xFF2056` bit1，返回 9 字节
  （`SPSDR` + 2 数据字节 + 校验 + `;`）。校验 = 前 7 字节之和。
  （固件里对 `D` 的检查是死代码，实际只强制第 3 字节为 `R`。）

**Python 参考（发送 SP 帧）**：

```python
def sp_frame(body: bytes) -> bytes:
    """ body 不含 'S''P'；自动计算原始字节校验并补 ';'。"""
    head = b'SP' + body
    chk  = sum(head) & 0xFF
    return head + bytes([chk]) + b';'

# SPW: 写 0x0123 = 0x45, 0x67
print(send_raw(ser, sp_frame(b'W\x01\x23\x45\x67')))   # -> b'A;'

# SPR: 读 0x0100
print(send_raw(ser, sp_frame(b'R\x01\x00')).hex())     # 5350520100 <d0 d1> <chk> 3b

# SPr: 读设置表 0x0A（地址为大端：hi=0x00, lo=0x0A）
print(send_raw(ser, sp_frame(b'r\x00\x0a')).hex())     # 535072000a 1f 3b（回包含 0x00 保留位）

# SPN: 读当前服务菜单项目号 N（0xFFAB00；hi=lo=FF）
print(send_raw(ser, sp_frame(b'N\xff\xff')).hex())     # 53504e <hi lo> <chk> 3b

# SPARD: 导出设置表（需 0xFF2020 bit7 允许，否则 b'?;'）
print(len(send_raw(ser, sp_frame(b'ARD'))))            # 378
```

### 7.7 安全与风险（务必阅读）

- **写类**：`SP`（尤其 `SPA*`、`SPw`）、`PE`、`JP` 会写**校准 / 设置 / 启动参数**，
  可能导致发射指标改变或**无法开机**。`ZZ` 会**立即复位**。
- **建议顺序**：
  1. 先用**只读**命令验证链路：`VE`、`FD00x`、`KT`、`PE000/100/200`、`E0`、`E8`、
     `SPR` / `SPr` / `SPARD`（读）。
  2. 写类命令仅在**能重刷固件、且理解后果**时使用。
  3. 操作前备份固件文件与原始设置。
- **二进制帧注意**：`SP` 校验字节或参数若等于 `0x3B` 会被误判为帧尾。
- **免责**：本节为**静态逆向**结论，**未在真机验证**；请自行评估风险。
