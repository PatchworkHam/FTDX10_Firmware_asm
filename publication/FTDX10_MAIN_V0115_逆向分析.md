# Yaesu FTDX10 固件容器、配置存储与控制链逆向分析

### ——基于 MAIN V01-15 的静态研究

2026 年 10 月

---

## 摘要

本文以 Yaesu FTDX10 的 MAIN V01-15 更新包为对象，给出一套不依赖动态调试的固件结构分析方法。研究确认：SFL 容器采用 576 字节文本头、43 字节固定置换密钥的逐字节减法混淆，以及覆盖密文数据段的 CRC-32 校验；MAIN 镜像由 H8SX/1645 执行，固件更新与恢复逻辑位于 DISPLAY 侧。通过重建 32 KiB FRAM 分区和 246 个访问点，本文定位了配置字节、用户设置、VFO 与信道记录等关键数据；通过控制流和交叉引用分析，揭示了前面板 8 个短接点中仅 EXP 位被现场读取、功率与区域选择位不被采用。进一步分析了功率控制的双重固件闸门、5 个单字节差异，以及 126 条 CAT 命令中的 24 条未公开命令。结果表明，该平台的安全边界主要依赖固定密钥混淆与 CRC 完整性校验，而非密码学认证；具备本地固件或 CAT 访问能力的攻击者可触及配置、校准与调试接口。

**关键词：** Yaesu FTDX10；H8SX；SFL；FRAM；CAT；固件安全；逆向工程

## 1. 引言

现代业余无线电收发信机通常由多个处理单元组成：主控 MCU 负责整机状态、配置存储和前面板接口，显示单元负责人机界面与升级流程，DSP/SDR 单元负责信号处理。与通用计算平台相比，这类设备的固件更新包、配置存储和调试接口往往缺少公开文档，形成了一片介于嵌入式系统与专用设备之间的“灰盒”区域。

FTDX10 是 Yaesu 推出的一款 HF/50/70 MHz 收发信机。其 MAIN 单元使用 Renesas H8SX/1645（`R5F61645N50FPV`，512 KB Flash、40 KB RAM、LQFP-144）[2]，DISPLAY 单元使用 ARM 处理器。厂商通过 SD 卡发布 `.SFL` 格式的更新包，包内包含 MAIN、DISPLAY、IFDSP、SDR 和 AFCPU 五个组件[4]。设备还保留了一组前面板短接点、外置 FRAM 配置存储器，以及与手册命令共用解析器的 CAT 串口。

本文关注四个问题：

1. SFL 更新包如何组织，完整性校验保护到什么程度；
2. 设备配置如何存储在外部 FRAM 中，哪些路径会改写配置；
3. 前面板短接点与功率控制链之间是否存在真实的固件通路；
4. 固件中是否存在未公开的 CAT 命令，其能力边界如何。

研究方法以静态分析为主：对更新包进行字节级解码，对 MAIN 镜像进行反汇编，结合交叉引用、控制流、常量表和原始字节比对重建数据流。文中地址均为 MAIN 镜像的文件偏移，关键结论均给出对应地址或字节，便于独立复核。

## 2. 研究对象与更新包构成

### 2.1 目标镜像

MAIN 镜像长度为 259,668 字节（`0x3F654`），覆盖文件偏移 `0x000000–0x03F653`。该范围包含复位向量、应用代码、常量表、默认设置块和版本字符串，是更新包实际写入的用户 MAT 区域。镜像中的地址与文件偏移一致，因此后文不再区分“文件偏移”和“运行时地址”。

DISPLAY 镜像为 ARM 裸二进制，长度为 3,373,532 字节；其运行时地址为文件偏移加 `0x20100000`。IFDSP 与 SDR 组件分别以裸二进制和十六进制文本形式交付；AFCPU 与 MAIN 则以 Motorola S-record 文本形式交付。

### 2.2 五个更新组件

**表 1　FTDX10 更新包的组成**

| 组件 | 类型码 | 版本 | 容器大小（字节） | 明文形式 |
|---|---|---:|---:|---|
| MAIN | `MC` | V01-15 | 738,986 | S-record 文本 |
| DISPLAY | `PC` | V01-06 | 3,374,108 | ARM 裸二进制 |
| SDR | `SR` | V01-00 | 4,392,794 | 十六进制文本 |
| IFDSP | `ID` | V01-20 | 139,036 | 裸二进制 |
| AFCPU | `AD` | V01-00 | 248,734 | S-record 文本 |

五个组件共享同一套 SFL 容器格式，但载荷类型不同；五个组件均能完成容器解码与载荷装配。MAIN 的 S-record 包含 16,230 条数据记录，全部记录的校验和均通过，说明解码结果与原始载荷自洽。

## 3. SFL 容器与完整性保护

### 3.1 容器结构

SFL 文件由两部分组成：

- 前 576 字节为文本头，共 9 行，以 CRLF 分隔，包含文件名、产品名、固件版本、日期、版权信息，以及一行元数据；
- 从偏移 576 开始为数据段，长度与明文载荷基本一致。

元数据行给出三个字段：

```text
<TYPE>  <SIZE>  <CRC32HEX>
```

其中 `TYPE` 为组件类型，`SIZE` 为整个 SFL 文件的字节数，`CRC32HEX` 为厂商校验字段。

### 3.2 逐字节减法混淆

数据段的“加密”不是分组密码，而是以 43 字节固定密钥进行的逐字节减法：

```text
P[i] = (C[i] - K[i mod 43]) mod 256
```

其中 `C` 为容器中的密文字节，`P` 为解密后的载荷，`K` 为 43 字节密钥。该密钥是整数 1 到 43 的一个置换，没有重复或遗漏。变换不改变长度，也没有扩散效应，因此明文中的长串填充字节会在密文中呈现明显的周期 43 结构。

这种方法更准确的描述是“固定密钥混淆”，而不是现代意义上的加密。其安全性不依赖于秘密：密钥长度、置换性质和周期都可以从样本中恢复。

### 3.3 CRC-32 校验

元数据中的 `CRC32HEX` 由下式给出：

```text
CRC32HEX = CRC-32/ISO-HDLC(C || A6 EC 9E 13)
```

其中 `C` 是偏移 576 之后的完整密文数据段，`A6 EC 9E 13` 是固定 4 字节尾。多项式为 `0xEDB88320`，初值为 `0xFFFFFFFF`，输出取反。对五个组件复算，结果均与头部声明值一致。

该字段能检测传输或打包错误，但它不是消息认证码，也不提供来源认证。任何能够改写容器的人都可以按同一算法重新计算校验值。因此，更新包的完整性保护应被理解为“防损坏”，而不是“防伪造”。

## 4. 启动、升级与恢复架构

### 4.1 更新逻辑位于 DISPLAY 侧

MAIN 镜像中可以看到与升级相关的界面文本，但在 259,668 字节的可见范围内，没有发现 Flash 自编程特征：没有 `FKEY` 解锁序列，没有 `FMATS` 写操作，也没有访问 H8SX Flash 控制寄存器的指令。MAIN 因而不是自我更新的主体，而是被外部写入的目标。

升级与恢复逻辑集中在 DISPLAY 固件中，分为两层：

1. **应用层升级界面**：负责识别 SD 卡中的 SFL 文件、按组件前缀匹配文件、显示校验与写入状态；
2. **独立 BOOT LOADER**：在应用固件无法启动时提供恢复通道，显示 `FIRMWARE BOOT ERROR`、`INSERT FIRMWARE SD CARD`、`MAIN FIRMWARE UPDATE` 等提示，并可按步骤重写 MAIN 与 DISPLAY。

BOOT LOADER 还能从 SD 卡根目录加载显示固件或引导器本体文件。这构成了设备的保底恢复能力，也使 DISPLAY 侧成为整个更新链的信任根。

### 4.2 整包更新而非差分更新

SFL 的 `SIZE` 字段描述整个文件，`CRC32` 覆盖整个密文数据段，载荷本身也是完整镜像。以 MAIN 为例，S-record 覆盖 `0x0–0x3F653`，包含复位向量和映像尾部版本串；只含少量改动记录的小型 S-Record 既不符合头部语义，也无法构成完整可启动镜像。

因此，任何针对 MAIN 的修改，若要进入厂商更新流程，都必须保持完整镜像结构、记录校验和与容器 CRC 自洽。

### 4.3 信任边界

从静态逻辑看，更新链的信任边界可以概括为：

**图 1　更新链的信任边界**

```text
SD 卡 / SFL 文件
        │
        ▼
DISPLAY 应用层 ── 文件识别、长度与 CRC 校验
        │
        ▼
DISPLAY BOOT LOADER ── 恢复通道、整包写入
        │
        ├──► MAIN Flash
        ├──► DISPLAY Flash
        └──► DSP / SDR 上传通道
```

在可见代码和字符串中，未发现非对称签名、证书链或设备唯一密钥参与更新包验证的证据。更新包的接受条件主要是格式、长度和 CRC-32。这意味着，掌握容器格式的人可以构造出通过校验的包；更新链的安全性更多依赖“格式不公开”和“设备本地访问”，而不是密码学认证。

## 5. FRAM 配置存储

### 5.1 器件与地址空间

MAIN 外置一颗 MB85RS256A FRAM，容量 32 KiB，地址范围 `0x0000–0x7FFF`[3]。固件通过四个原语访问它：

- 字节读：`0xA4A8`；
- 字节写：`0xA528`；
- 块读：`0xA4E2`；
- 块写：`0xA5C2`。

对全部代码进行交叉引用扫描，共找到 246 个访问点：162 次字节写、21 次字节读、38 次块写、25 次块读。按地址来源分类，112 处可由常量直接确定，88 处由函数参数传入，31 处由运行时计算，15 处仍无法静态确定。FRAM 地址与固件文件偏移一致，四个原语的机器码也已逐字节核对。

### 5.2 分区重建

32 KiB 空间被划分为 27 个连续区间，首尾相接、无空洞、无重叠。表 2 列出与本文结论直接相关的区域。

**表 2　FRAM 主要分区**

| 区间 | 大小 | 用途 |
|---|---:|---|
| `0x0002–0x0005` | 4 B | 两个 16 位魔数槽，用于设置表有效性判断 |
| `0x0006–0x0007` | 2 B | 配置字节对，镜像到 RAM `0xFF2006/07` |
| `0x000A–0x017C` | 371 B | 内部设置表，整块镜像到 RAM `0xFFA948` |
| `0x0300–0x048F` | 400 B | 用户设置块，含菜单项与功率限值 |
| `0x0490–0x0A7F` | 1,520 B | 消息存储区，含 CW/RTTY/PSK 文本记录 |
| `0x0A80–0x0C11` | 402 B | 100 条目的环形日志 |
| `0x0C12–0x277D` | 7,020 B | 频段堆栈，6 组 × 13 条 × 90 B |
| `0x2BC3–0x2C76` | 180 B | VFO-A / VFO-B 当前状态 |
| `0x2C99–0x55BA` | 10,530 B | 117 条存储信道 × 90 B |
| `0x55BB–0x5A4C` | 1,170 B | 13 条 5 MHz 预设 × 90 B |
| `0x5B29–0x7FFF` | 9,431 B | 正常路径未引用，但服务命令可写入 |

配置字节对是整机行为的核心。`FRAM[0x0006/0x0007]` 在启动时被读入 RAM `0xFF2006/0xFF2007`，并在设置保存时写回。`0xFF2007` 的位定义如下：

| 位 | 字段 | 含义 |
|---|---|---|
| bit0–2 | TS | 波段方案变体选择 |
| bit3–4 | PWR | 功率档 |
| bit5 | EXP | 频率覆盖/发射范围扩展 |
| bit6–7 | AUX | 保留 |

这一字节既影响菜单可见范围，也影响功率上限。后文将说明，前面板短接点并没有改变它。

## 6. 前面板短接矩阵

### 6.1 拓扑与极性

MAIN 单元的原理图给出 8 个配置短接点，分别对应 TS0–TS2、PWR0–PWR1、EXP、AUX0–AUX1。8 只二极管的阳极接 KSC 列，阴极经跳线接到 KR0–KR7；KR0–KR7 各有 4.7 kΩ 下拉，并经串阻进入 MCU 的 Port K。

KSC 由 PC2 驱动（引脚 116）。当 KSC 为高、跳线焊接时，对应 KR 线被抬到接近 Vcc，MCU 读到 1；跳线断开时，4.7 kΩ 下拉使 MCU 读到 0。因此极性为：

```text
KRn = 1  ⇔  跳线焊接且 KSC 为高
```

固件侧没有取反。`0xA76` 选择 KSC 列、延时并读取 `PORTK`，`0xA60` 通过连续两次相同读数完成去抖，再把结果交给配置处理例程。

### 6.2 8 个短接点的实际采用情况

**表 3　短接点与配置位**

| 跳线 | 网络 | KR 线 | 端口位 | 配置位 | 本版是否采用 |
|---|---|---|---|---|---|
| JP1001 | TS0 | KR0 | PK0 | bit0 | 否 |
| JP1002 | TS1 | KR1 | PK1 | bit1 | 否 |
| JP1003 | TS2 | KR2 | PK2 | bit2 | 否 |
| JP1004 | PWR0 | KR3 | PK3 | bit3 | 否 |
| JP1005 | PWR1 | KR4 | PK4 | bit4 | 否 |
| JP1006 | EXP | KR5 | PK5 | bit5 | **是** |
| JP1007 | AUX0 | KR6 | PK6 | bit6 | 否，且被强制清零 |
| JP1008 | AUX1 | KR7 | PK7 | bit7 | 否 |

关键结论是：物理上 8 个点都在 KSC 列上，但本版固件中只有 EXP（bit5）会被现场重新读取并写回配置字节；TS、PWR、AUX 位不参与配置生成。

### 6.3 两条配置路径

从启动调用链可以区分两条路径：

**图 2　短接点配置路径**

```text
活路径：
0x1570 → 0x8E50 → 0x8E54 → 0xA38
                              ├─ 读 PORTK（0xFFFBA3）
                              ├─ cfg7 = (cfg7 & 0x9F) | (PORTK & 0x20)
                              └─ 0xA58 写回 0xFF2007

不可达路径：
0x7D2E → 0x7E8E → 0x7E9E → 0xA26
                              └─ 把 PORTK 整字节写入 0xFF2006/07
```

`0xA38` 的掩码 `0xFF9F` 保留了 bit3/4（PWR），清除了 bit6，再或入 bit5（EXP）。`0xA58` 是该例程尾部的写回指令，不是独立函数。对 `0xA26` 所在路径的入口 `0x7D2E` 做三类检查——反汇编文本引用、32/24 位常量、分支与调用目标——结果均为零；因此“跳线整字节写入配置”的路径在本镜像中不可达。

这也解释了为什么短接 PWR0/PWR1 不会改变功率档：功率档最终来自 FRAM 配置字节，而不是跳线矩阵。EXP 是唯一例外，它仍可通过 JP1006 改变频率覆盖行为。

## 7. 功率控制链

### 7.1 两个固件闸门

功率档由配置字节 `0xFF2007` 的 bit3/4 决定：

| 编码 | 档位 |
|---|---|
| `0x18` | 100 W |
| `0x00` | 50 W |
| `0x08` | 20 W |
| `0x10` | 10 W |

该字段进入两个相互独立的固件闸门。

**第一道闸门：菜单区间表。** 基址为 `0x159F6`，按“频段组 × 档位”排列，每项是一对 `(min, max)` 字节。RF POWER 与 MAX POWER 菜单在调整时读取该表，决定用户能把数值推到多高。

**表 4　各档位在各频段组的菜单上限（W）**

| 档位 | HF | 50 MHz | 70 MHz | AM |
|---|---:|---:|---:|---:|
| 100 W | 100 | 100 | 50 | 25 |
| 50 W | 50 | 50 | 50 | 25 |
| 20 W | 10 | 20 | 20 | 20 |
| 10 W | 10 | 10 | 10 | 10 |

对于 50 W 机器，HF 行的上限就是 50，这是第一个限制。

**第二道闸门：等级钳位。** `0x3BCA0` 根据档位限制功率等级：100 W 档不钳位；50 W 档限制到等级 4；20 W 档限制到等级 3，部分子带进一步限制到等级 2；10 W 档限制到等级 2。因此，即使菜单值被改大，最终等级仍会被钳住。

### 7.2 有效功率与用户设置

实际发射功率取两个用户设置的最小值：

```text
P_eff(b) = min(F(b), AC(b))
```

其中 `F` 是面板 RF POWER 设定，`AC` 是各频段 MAX POWER 上限。两者分别对应：

- `F`：RAM `0xFFAAF1–0xFFAAF4`，FRAM `0x0335–0x0338`；
- `AC`：RAM `0xFFAC26–0xFFAC29`，FRAM `0x046A–0x046D`。

即使把档位改成 100 W，用户仍需要在菜单中把 F 和 AC 推到 100，才能得到 100 W 的有效设定。最终是否真正输出 100 W，还取决于末级功放和驱动硬件是否与 100 W 机型一致。

### 7.3 5 个单字节差异

对 `0xFF2007` 的消费者做全量交叉引用，可以找到 7 处以该字节为输入执行 `and.b #0x18` 的位置。其中 5 处直接参与默认值、菜单范围或钳位；另外 2 处只做有效性判断。

把这 5 处的“取档”指令改为“直接给 100 W 档”，得到一组 5 个单字节差异：

**表 5　用于验证控制链的 5 个单字节差异**

| 偏移 | 原字节 | 新字节 | 原指令 → 新指令 | 作用 |
|---|---|---|---|---|
| `0x08112` | `E8 18` | `F8 18` | `and.b #0x18,r0l` → `mov.b #0x18,r0l` | FRAM 默认初始化按 100 W 写入 F/AC |
| `0x1595C` | `E0 18` | `F0 18` | `and.b #0x18,r0h` → `mov.b #0x18,r0h` | RF POWER 菜单取 100 W 档 |
| `0x159D4` | `E0 18` | `F0 18` | `and.b #0x18,r0h` → `mov.b #0x18,r0h` | MAX POWER 菜单取 100 W 档 |
| `0x3BB8A` | `EE 18` | `FE 18` | `and.b #0x18,r6l` → `mov.b #0x18,r6l` | 取消 20 W 档的 HF 10 W 硬限 |
| `0x3BCA6` | `EA 18` | `FA 18` | `and.b #0x18,r2l` → `mov.b #0x18,r2l` | 功率等级钳位取 100 W 档 |

这组差异只改消费点，不改配置字节本身。因此 TS、EXP、AUX 位不受影响；即使配置字节之后被重写，这 5 个点也不再使用原档位，补丁效果不会被撤销。它验证了“功率限制由消费点决定”这一控制链结论。

固件修改只能解除固件层限制；若末级功放、驱动或散热设计不同，修改固件不会自动获得相应的硬件能力。

## 8. 未公开 CAT 命令面

### 8.1 命令表规模

MAIN 固件中的 CAT 命令分派表位于 `0x27CF2`，共 126 条 2 字节命令码；处理函数指针表位于 `0x27AFA`，每项 4 字节。CAT 手册列出的命令为 102 条[1]，因此有 24 条命令码只存在于固件中。

这 24 条中：

- 13 条是禁用桩，处理函数只跳转到错误回复 `?;`：`AN BG DP DS FK FR FS KC MK RO SY VF VT`；
- 11 条具有真实处理逻辑：`EK EO FD KT PE SP VE JP ZZ E0 E8`。

两条 CAT 通道共用同一张命令表和同一套解析器。未公开命令不需要特殊端口或隐藏模式，只要能与 CAT 接口通信，就会进入同一派发路径。

第二个解析器使用 252 作为扫描上界，而表实际只有 126 条；越界扫描可能落入后续代码，但派发器以 125 为最大索引，任何越界命中都会被拒绝，因此不会产生额外的有效命令。这一细节说明，命令面的真实边界由派发器而不是扫描计数决定。

### 8.2 代表性命令

**表 6　具有实际逻辑的未公开 CAT 命令**

| 命令 | 能力概要 |
|---|---|
| `SP` | 外部 FRAM 与内部设置表读写；`SPW/SPR` 访问 FRAM，`SPw/SPr` 访问 371 B 设置表，`SPARD` 可整块读出设置表 |
| `PE` | 参数/校准表按子命令读写，并访问总线 |
| `JP` | 以 `0010` 为前缀读写 `0xFF2006/07`，并搬运 `0x2F0 × 5` 参数区；不触发复位 |
| `ZZ` | 以 `PE0010` 为前缀写入 `0xFF2002`，随后软复位 |
| `E0` | 返回 229 字节带掩码与校验的诊断帧 |
| `E8` | 返回 10,573 字节内存/数据区转储 |
| `FD` | 读写一组 32 位频率/数据寄存器 |
| `VE` | 版本/ID 查询；参数为 7 字节魔术串 `RAH076H`，完整帧为 `VERAH076H` |
| `KT` / `EK` | 写入 CW 文本缓冲，或调用同一子系统 |

`SP` 是权限最高的一条。它把外部 FRAM 的读写原语直接暴露给 CAT 接口，地址范围覆盖 32 KiB 空间；`SPw/SPr` 则面向内部设置表，`SPARD` 可一次读出 371 字节完整配置。`PE` 面向校准/参数表，`JP` 可改写配置字节和参数区，`ZZ` 可强制重启。`E8` 的单次转储超过 10 KB，足以泄露大块内部状态。

## 9. 结论

本文从容器、存储、硬件配置、功率控制和 CAT 接口五个层面还原了 FTDX10 MAIN V01-15 的关键结构，得到以下结论：

1. SFL 使用 576 字节文本头、43 字节固定置换密钥的逐字节减法混淆，以及覆盖密文数据段的 CRC-32 校验；它能防损坏，但不能防伪造。
2. 更新与恢复逻辑位于 DISPLAY 侧，MAIN 在可见镜像中没有 Flash 自编程能力；更新包是完整镜像，而不是差分包。
3. FRAM 的 32 KiB 空间可划分为 27 个连续区域，配置字节、用户设置、VFO 与信道记录均可定位；246 个访问点显示出配置存储与运行时设置之间的紧密耦合。
4. 前面板 8 个短接点中，只有 EXP（bit5）被活路径采用；TS、PWR、AUX 位不参与配置生成。功率档来自 FRAM 配置字节，而不是跳线。
5. TS（`FRAM[0x0007]` bit0–2）选择 8 张波段边界表（`0x32B2A`）：只有 **TS=2/3/7** 含 5 MHz，只有 **TS=2** 含 70–70.5 MHz，**TS=7** 的 HF 最宽；EXP=1（bit5）会整体替换 TS 表（1.8–30 / 50–54 / 70–70.5），服务模式 `0xFF2020.7` 则为 1.8–75 MHz。MAIN 侧 TX 状态机 `0x3CC20` → `0x3D0C2` 直接以 `0x3D1F2`→`0x32A70` 的频段表结果为门闩：越界（carry clear）清 `0xFFFBA4.2`，在段内（carry set）置位；`0xFF2014.5` 的极性是 **1=在频段内，0=越界**。因此 TS/EXP/服务模式不仅改变显示范围，也直接决定 MAIN 侧 TX 许可。详见 `TS/`。
6. 功率限制由菜单区间表和等级钳位两道固件闸门共同实现；5 个单字节的消费点差异可以验证这条控制链，但不会改变硬件能力。
7. CAT 命令表包含 126 条命令，其中 24 条未在手册中公开；11 条具有真实逻辑，覆盖 FRAM、校准、参数区、内存转储和软复位。它们与用户命令共用入口，没有额外认证。
8. 更新链的完整性保护由固定密钥混淆、CRC-32 和格式约束组成，未发现签名、证书或设备唯一标识绑定；CRC-32 可由任何改写者重算，FRAM 配置与未公开 CAT 命令之间也没有统一的认证机制。

总体而言，FTDX10 的更新链与配置、调试接口依赖固定密钥混淆、CRC 校验和未公开命令，没有建立密码学信任边界。对于具备本地固件或 CAT 访问能力的攻击者，配置、校准和调试接口仍然是可达的。

上述结论基于 MAIN V01-15 的静态镜像分析，未进行真机写入、射频测量或故障注入；未取得真实 FRAM 转储，部分字段名称仍为推断，246 个访问点中 15 个地址无法静态确定。
